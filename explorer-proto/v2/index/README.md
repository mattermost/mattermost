# Coverage index and duplicate gate (pilot v2, WP-B)

A deterministic, code-only index of every existing end-to-end test, and a gate that ranks the existing tests most
similar to a candidate journey. No LLM, no embeddings, no network, no test execution. **Code ranks; an agent or a
human judges equivalence.** The gate never prints "equivalent".

Plain Node 24 (`.mjs`). Parsing uses the TypeScript compiler API already installed in
`e2e-tests/playwright/node_modules/typescript` (loaded by path; nothing is added to any `package.json`).

## Usage

```bash
# 1. Build the index for the current checkout (about 4 s for the whole repo)
node explorer-proto/v2/index/extract.mjs --out=/tmp/idx          # --out is optional, see "Cache"

# 2. Gate a candidate journey
node explorer-proto/v2/index/coverage-check.mjs --index=/tmp/idx --candidate=my_candidate.json [--k=8] \
    [--exclude-sessions] [--include-emitted] [--json]

# 3. Ground-truth evaluation, self tests
node explorer-proto/v2/index/evaluate.mjs [--index=/tmp/idx] [--out=eval/RESULTS.md] [--json]
node explorer-proto/v2/index/selftest.mjs [--update-golden]
```

`extract.mjs` flags: `--out=<dir>`, `--repo-root=<dir>` (tests use `fixtures/repo`), `--sha=<label>` (overrides
`git rev-parse HEAD`, used by the golden test), `--no-explorer` (skip `explorer-proto/**` specs).
`--index` may be omitted on `coverage-check`/`evaluate`: the cache entry for the current checkout is used and built if
missing.

### What is indexed

| Source                  | Scope                                                                                                                                                                                                                                                                                                                                                     |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cypress                 | every `.js`/`.ts` under `e2e-tests/cypress/tests/integration` (tests found by AST: `describe`/`context`/`it`/`specify`, `.skip`/`.only`, hooks)                                                                                                                                                                                                           |
| Playwright              | `e2e-tests/playwright/specs` and `e2e-tests/playwright/upgrade-specs` (`test`, `test.describe[.serial/.parallel]`, `.skip`/`.fixme`/`.only`, `test.beforeEach/beforeAll`, `test.step`)                                                                                                                                                                    |
| Helpers, one level deep | Cypress custom commands (`Cypress.Commands.add/overwrite` under `cypress/tests/support`), local and imported functions (relative, `@/` alias, `export *` re-exports, `@mattermost/playwright-lib` exports from `lib/src`), Playwright page-object classes under `lib/src/ui` (methods, getters, fields, constructor-assigned locators, nested components) |
| Explorer specs          | `explorer-proto/generated/*.spec.ts` and `explorer-proto/sessions/*/generated/*.spec.ts`, `origin: session`                                                                                                                                                                                                                                               |

`origin` is `repo` (normal), `session` (`explorer-proto/**`) or `emitted` (a spec under `e2e-tests/` whose first 1500
bytes mention `explorer-proto`, `@explorer_pilot`/`@explorer_session` or `Generated by explorer`). The gate default
compares against `repo` + `session`. `--exclude-sessions` drops `session`; `--include-emitted` adds `emitted` (so a
spec emitted by an earlier pilot into `e2e-tests/playwright/specs` is not its own duplicate unless asked).

### Per-test record (`tests.jsonl`, one JSON object per line)

`id` (`file:line`), `suite`, `origin`, `file`, `line`, `end_line`, `title` (+`title_dynamic`), `describe[]`, `tags[]`
(`@tags` in titles and `{tag}` options; `// Stage:`/`// Group:` header comments for Cypress), `stage`, `mm_t_ids[]`,
`skipped`, `objective` (`@objective` JSDoc), `narrative[]` (`// #` and `// *` step comments), `actors {count, keys[]}`,
`setup[]` (`name`, `detail[]` such as `config:Section.Key`, `pref:cat.name`, `flag:Name`), `actions[]`
(`seq`, `verb`, `target`, `label`, `at`, optional `via`, `phase`, `depth_limited`), `assertions[]` (`seq`, `kind`,
`matcher`, `target`, `negated`, `expected[]`, `at`, optional `via`, `phase`), `locators[]`, `fingerprint`,
`fingerprint_loose`, `source_status` (`extracted|partial`), `partial_reasons[]`, `notes[]`.

- `at` is `repo-relative-path:line` of the node that was read. For an event inside a resolved helper it is the helper's
  own file:line and `via` is the call site in the test. No absolute paths, no timestamps; records are sorted by
  file then line, so the output is byte-identical between runs (checked by `selftest.mjs`).
- `phase: "hook"` marks events from `before`/`beforeEach` hooks that apply to the test. They count for UI labels and
  setup, not for the structural fingerprint.
- Label grammar: `role:button[name=View Info]`, `text:...`, `testid:...`, `label:...`, `placeholder:...`,
  `css:...`, `alias:...`, composed with `>` (`testid:channel-bookmarks-container > role:link[name=Docs]`). Template
  strings keep their static parts and show runtime parts as `{expr}`. Regex locators keep their literal text.
  Helper calls are `call name(static args)`; page-object calls are `call Class.method(...)`.
- Actors: distinct keys among `pw.testBrowser.login(x)`, `pw.makeClient(x)`, `cy.apiLogin(x)`, `cy.apiAdminLogin()`,
  `cy.postMessageAs({sender})`, `apiInitSetup({loginAfter})`, `newPage`/`newContext`. Setup-only logins count, so the
  number is an upper bound on UI actors.
- Fingerprints: `sha1(JSON(ordered action labels, ordered assertion target|matcher, actor count))[:16]`, with digits,
  hex ids and `{...}` placeholders stripped; `fingerprint_loose` hashes the sorted unique sets instead of the order.

### `source_status: partial` reasons

| Reason                                                     | Meaning                                                                                                                       |
| ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `dynamic_locator:<method>`                                 | a locator argument has no static content at all (`cy.findByText(user.username)`, `page.locator(selector)`)                    |
| `unresolved_helper:<name>`                                 | imported helper that is relative/aliased/lib but could not be found                                                           |
| `unresolved_cy_command:<name>`                             | `cy.<name>` is neither a known built-in/plugin command, an `api*`-style setup command, nor defined in `cypress/tests/support` |
| `unresolved_page_object_member:<Class.member>`             | member missing on the resolved page-object class (often a name-based false positive such as `passwordSettings.Lowercase`)     |
| `loop_generated_test`                                      | test registered inside a loop/`forEach` with a runtime title                                                                  |
| `helper_depth_limit_only` / `no_actions_or_assertions`     | nothing but unexpanded helper calls, or nothing at all, was found in the test body                                            |
| `test_body_unresolved`, `parse_error`, `event_cap_reached` | structural problems (cap is 600 events per test)                                                                              |

Helpers called from inside a resolved helper are not expanded (the rule is one level). They are kept as
`call name()` actions flagged `depth_limited` and listed in `notes`; they do not make a test partial.

## Similarity (`fingerprint.mjs`, `similarity.mjs`)

Normalization (shared by both sides): lowercase; split camelCase and punctuation; drop `{...}` placeholders, hex ids,
`MM-T` ids and digits (counters); drop stop tokens (grammar words, label-kind prefixes `css`/`text`/`role`/`testid`,
`ui`/`api`/`cy`/`pw`, boilerplate such as `click`, `visible`, `should`); light stemming (`ies`->`y`, `ing`, `ed`,
`es` after `s/x/z/ch/sh`, plural `s`, trailing `e`: `archived`, `archive` and `archiving` all become `archiv`).

For each field the weight of a token is `w(t) = ln(1 + N / (1 + df(t)))`, with `N` the number of compared tests and
`df` the number containing the token in that field (an IDF, so `channel` is cheap and `bookmark` is expensive). It is
recomputed per query over the filtered corpus.

| Component     | Candidate side                                                   | Test side                                                                                               | Value in [0,1]                                                                                                                                                                               |
| ------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ui`          | `ui_labels` + `checkpoints[].labels`, one phrase each            | segments (split on `>`) of action targets/text and every locator                                        | label level: for each candidate label `c`, `best_c = max_l Dice_w(c, l)`; `ui = sum(m_c * best_c) / sum(m_c)` with `m_c = sum w(t in c)` and `Dice_w = 2*sum_{t in c and l} w / (m_c + m_l)` |
| `assertion`   | `checkpoints[].labels` + `checkpoints[].expected_text`           | segments of assertion targets and expected strings                                                      | same label-level rule                                                                                                                                                                        |
| `goal`        | `title` + `goal_terms` + checkpoint descriptions                 | title, describe chain, `@objective`, `//#`/`//*` narrative, tags, path tokens (generic folders removed) | token level: `0.7 * R + 0.3 * F1` where `R = sum w(shared)/sum w(candidate)`, `P = sum w(shared)/sum w(test)`                                                                                |
| `actor_setup` | `actors.length`, `setup[]`                                       | `max(1, actors.count)`, setup names + details                                                           | `0.4 * (1 - abs(a-b)/max(a,b)) + 0.6 * blend(setup tokens)`; one term alone when the other is empty                                                                                          |
| `tags`        | `MM-T` ids, `@tags` in title/goal/descriptions, `testid:` labels | `mm_t_ids`, tags, `testid:` locators                                                                    | fraction of cited ids found; **not applicable** when the candidate cites none                                                                                                                |

`score = sum(W_k * c_k) / sum(W_k)` over the components that apply, with
`W = {ui: 0.35, assertion: 0.25, goal: 0.20, actor_setup: 0.15, tags: 0.05}`. A component with an empty candidate side
is dropped and the others are re-normalized.

`label_coverage` (per component and combined) is the weight-share `sum(m_c : best_c >= 0.6) / sum(m_c)` of candidate
labels that a single test label matches strongly. It is the evidence gate used by the verdict.

### Verdict (any of the top-k results may qualify; first matching rule wins)

| Verdict            | Rule                                                                                                                   |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| `likely_duplicate` | `score >= 0.70` and `ui` label coverage `>= 0.80` and `assertion` label coverage `>= 0.80` (a missing side is ignored) |
| `needs_review`     | `score >= 0.35` and combined label coverage `>= 0.34`                                                                  |
| `no_close_match`   | otherwise                                                                                                              |

`likely_duplicate` means "compare these first", not "equivalent". Every result prints three axes side by side so the
reviewer can judge: (1) actors + setup, (2) transition labels (candidate `ui_labels`/labels vs the test's ordered
actions, `*` marks matched labels, `h` marks hook steps, each with file:line), (3) final assertions (last checkpoint vs
the test's last five assertions). Matching assertions and UI labels list file:line and `via`.

### Candidate file

```json
{
    "title": "Bookmark bar follows an in-app channel switch",
    "actors": [{"id": "member", "role": "member"}],
    "setup": ["create two public channels", "create one link bookmark in each channel"],
    "goal_terms": ["channel bookmarks bar", "switch channel in-app"],
    "checkpoints": [{"description": "...", "labels": ["bookmark link"], "expected_text": ["optional visible text"]}],
    "ui_labels": ["testid:channel-bookmarks-container", "sidebar channel link"]
}
```

Only `title` is required. Labels are the names a user sees (or a `testid:` id); the gate matches them to roles, names,
texts, test ids and CSS id/class words, never to prose.

## Cache

`extract.mjs` without `--out` (and `coverage-check`/`evaluate` without `--index`) use
`explorer-proto/v2/index/.cache/<git sha12>-<corpus hash>-<extractor hash>/` (`tests.jsonl`, `meta.json`). The
directory is git-ignored by `explorer-proto/v2/index/.gitignore`. The key changes with the checkout SHA, the content of
every scanned test/helper file (so a dirty tree gets its own entry) and the extractor source, so an index is rebuilt per
SHA and never reused across extractor changes. The whole-repo index is about 32 MB; never commit it. Only the tools,
tests, `fixtures/`, `golden/` and `eval/` are committed.

## Limits: what static extraction cannot see

- Runtime values: selectors, titles and texts built from data (`cy.findByText(channel.display_name)`, loops over arrays
  of cases). They are labelled `{expr}` and counted as partial when nothing static remains.
- Helpers beyond one level (about 10k test-and-helper `depth_limited` notes repo-wide), helpers in node packages, dynamic dispatch and
  aliases (`cy.get('@alias')`, values captured by `.then` callbacks).
- Control flow: both branches of an `if` are walked in source order; nothing is executed, so skipped or
  data-dependent steps still appear and the order of `cy` callbacks is textual, not runtime.
- Page objects are resolved by variable name (`channelsPage` -> `ChannelsPage`) and by the class index of
  `lib/src`; page objects defined elsewhere or properties of unrelated objects that share a class-like name are
  misread (the small `unresolved_page_object_member` group).
- Cypress custom commands' returned subject is the last locator the body built; commands that return other things lose
  it. Regex locators are reduced to their literal text.
- Tests that assert only through CSS ids and classes (older Cypress specs) share no vocabulary with a candidate written
  in user-visible labels; they rank low even when a human would call them close. Fixtures, feature flags, licences and
  server configuration are visible only as setup call names and config keys.
- Actor count includes setup-only logins; it is a similarity hint, not the number of browsers.
- Equivalence is a semantic judgement about behaviour. The scores say how much vocabulary, structure and assertion
  evidence overlap, nothing more.

## Evaluation and parameter-change log

`evaluate.mjs` resolves each lead (file and approximate line) to the test whose `[line, end_line]` contains it (or the
nearest test, reported as a correction) and reports rank, recall@1/3/5/8 per expected test, per file and per candidate,
and the verdicts. `eval/RESULTS.md` is the committed output at the pinned SHA, `eval/NEGATIVES.md` documents how the
negative candidates were verified absent. Candidates in `eval/candidates/*.json` were written from the journey
descriptions and product labels (charters, `en.json`), before any run, not from the expected tests' bodies.

Initial parameters (fixed before the first run): weights `0.35/0.25/0.20/0.15/0.05`, blend `0.7/0.3`, actor/setup split
`0.4/0.6`, thresholds `needs_review 0.35`, `likely_duplicate 0.70` (with `ui >= 0.6`, `assertion >= 0.5`), IDF
`ln(1 + N/(1+df))`, bag-of-token overlap for every component, no stemming of trailing `e`.

Every change made after seeing results (expected-test recall @1/@3/@5/@8, 20 expected tests, sessions excluded):

| Run | Change                                                                                                                                   | Recall            | Negatives (no_close_match of 4)   |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------- | ----------------- | --------------------------------- |
| 0   | first build                                                                                                                              | 10/20/30/35%      | 2                                 |
| 1   | extraction bug fixes found by inspecting zero-action tests (`pw.<page>` read as an API call; helper calls below the depth limit dropped) | 10/20/30/35%      | 2                                 |
| 2   | stemmer: drop a trailing `e` (`archived` did not match `archive`)                                                                        | 10/20/30/40%      | 2                                 |
| 3   | BM25-style length normalization plus an evidence floor on the token bag                                                                  | 10/15/15/35%      | 2 (worse, **reverted**)           |
| 4   | label-level matching for `ui` and `assertion` (a candidate phrase must match one test label, not scattered tokens)                       | 15/25/25/30%      | 2                                 |
| 4b  | same, with the BM25 variant kept for `goal`/`setup`                                                                                      | 15/25/25/30%      | 2 (identical, simpler blend kept) |
| 5   | verdict gates on label coverage; `likely_duplicate` needs `>= 0.8` coverage on both sides                                                | ranking unchanged | 3                                 |

Runs 4 and 5 are principled (the spec asks for label overlap and a reviewer-facing gate), but they were chosen after
seeing that bag-of-token scores let common words imitate a phrase; read the numbers with that in mind. Thresholds were
not tuned after run 5. Later changes (a few more extraction fixes found while writing `selftest.mjs`: `api*` setup
commands without needing the command index, page objects reached through a login result, helpers re-exported from
npm packages) did not alter the recall numbers.
