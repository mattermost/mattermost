# Lessons from the earlier pilots, as proposals

`lessons.json` holds 13 lessons in the `explorer-lesson/v2` format (`explorer-proto/v2/schemas/lesson.schema.json`). It is a JSON array; each element is one lesson and validates on its own. Every lesson is `status: proposed`, `applied: false`, with no `approver`. Nothing here is approved, and nothing here is applied by any code. An agent cannot approve its own lesson.

## How to use them

- Roles read them: the checklists in `explorer-proto/v2/agents/roles/` already encode the agent-side part of each lesson, and each lesson names the role file where its check would live (`proposed_check.target_file`).
- The proposals are scoped to what agents and work-package owners do (fixtures, probes, reports, checklists). They name no gate, rule file, schema or threshold, so `lessons_guard.mjs` accepts them as written.
- Where a lesson would also justify a stronger deterministic check, the table says so. That change is a separate, human-approved change under `explorer-proto/v2/gates/POLICY-CHANGE.md` (an `approvals.json` entry bound to the combined hash, then a lesson with `status: approved` and a human `approver`). Do not edit the frozen gates because of this file.
- Verify them: `node explorer-proto/v2/agents/selftest.mjs` validates the file against the schema, runs `lessons_guard.mjs` over every lesson, and checks that every evidence path exists.

## Provenance

Eleven lessons rest on files committed in this repository. Two rest on the work-package brief only: L08 (phantom mention badge after a skipped viewed-last step) and L13 (replays on a polluted server change the channel introduction). No committed log records those incidents. The evidence listed for them shows the mechanism and the guard that now exists, not the incident itself. Treat them as reported, not reproduced here.

## Gate follow-ups a human could approve (not proposed as lessons here)

- L08, L09 and L13 have no deterministic check. A gate that reads fixture read-back counts, WebSocket connectivity or a clean-server marker would need a new module, a self-test and a hash approval.
- L12 would need the orchestrator to record the heuristic terms next to the budget in `5-discover` output.
- L05 for notes: extend the leakage scan to any file a runner can read.

These are listed so a person can decide. Each would be a reviewed change under `POLICY-CHANGE.md`, not something an agent applies.
