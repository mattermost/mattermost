# Authoring-tier i18n metadata

`en-with-description.json` pairs every key in `../i18n/en.json` with a
`description` explaining where the string appears and how it is used. The
descriptions are context for translators (human or AI); they are never shipped
to the client.

This directory is deliberately a sibling of `../i18n/` rather than a file
inside it. Everything that consumes `src/i18n/*.json` — the runtime language
imports generated by `webapp/scripts/gen_lang_imports.mjs`, `formatjs verify`,
and `scripts/check_icu.mjs` — expects flat `key -> string` locale catalogs, and
would treat a nested authoring file as a broken locale.

Regenerate after changing translatable strings:

    npm run i18n-extract-authoring

The generator keeps the key set and `defaultMessage` values in lockstep with
`en.json`. A `description` written in source (the `description` field of
`defineMessages` / `<FormattedMessage>`) always wins; otherwise the existing
curated description is preserved. New keys land with an empty description to
fill in.

`npm run i18n-extract-authoring:check` fails if the file is out of date.
