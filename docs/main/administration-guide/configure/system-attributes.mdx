<PlanAvailability slug="entry-ent" />

System attributes are the attributes Mattermost stores for users and channels, and the access policies that use them. Review and manage them in the System Console by selecting the **Product** <img src={useBaseUrl('/img/ui/products_E82F.svg')} alt="Navigate between Channels, collaborative playbooks, and boards using the product menu icon." className="theme-icon" /> menu, selecting **System Console**, and then selecting **System Attributes**. The section contains the following pages:

- **Attribute Management**: From Mattermost v12.0, define an attribute once and choose the resources it applies to, such as users and channels. Requires Mattermost Entry, Enterprise, or Enterprise Advanced. See [Attribute management](/administration-guide/manage/admin/attribute-management) and [Channel attributes](/administration-guide/manage/admin/channel-attributes). Before v12.0, user attributes were managed on a **User Attributes** page. See [User attributes (before v12.0)](/administration-guide/manage/admin/user-attributes).
- **Session Attributes**: Choose which details of a user's current connection, such as IP address, VPN status, and device posture, permission policies can check. Requires Mattermost Entry or Enterprise Advanced. See [Session attributes](/administration-guide/manage/admin/session-attributes).
- **Attribute-Based Access**: Turn attribute-based access control (ABAC) on and configure how it behaves. Requires Mattermost Entry or Enterprise Advanced. The settings on this page are described [below](#attribute-based-access).
- **Membership Policies**: Create system-wide policies that control who can be a member of channels and teams. Shown once attribute-based access control is enabled. See [System-wide attribute-based access policies](/administration-guide/manage/admin/abac-system-wide-policies).
- **Permission Policies**: Create policies that control who can upload and download files. Shown once attribute-based access control is enabled. See [Permission policies](/administration-guide/manage/admin/abac-system-wide-policies#permission-policies).

<Tip>

System admins managing a self-hosted Mattermost deployment can edit the `config.json` file as described in the following tables. Each configuration value below includes a JSON path to access the value programmatically in the `config.json` file using a JSON-aware tool. For example, the `SyncJobIntervalSeconds` value is under `AccessControlSettings`.

- If using a tool such as [jq](https://stedolan.github.io/jq/), you'd enter: `cat config/config.json | jq '.AccessControlSettings.SyncJobIntervalSeconds'`
- When working with the `config.json` file manually, look for an object such as `AccessControlSettings`, then within that object, find the key `SyncJobIntervalSeconds`.

</Tip>

Some of these settings have no System Console option and can only be changed in the `config.json` file or with an environment variable. Each one is marked **N/A** under System Config path.

#### What gets recorded

Each record covers one user and one channel or team. Mattermost records these events:

| Event | When it's recorded |
|----|----|
| `channelMembershipAdded` | A sync job added a user to a channel because they match its policy. |
| `channelMembershipRemoved` | A sync job removed a user from a channel because they no longer match its policy. |
| `teamMembershipAdded` | A sync job added a user to a team because they match its policy. |
| `teamMembershipRemoved` | A sync job removed a user from a team because they no longer match its policy. |
| `teamCascadedChannelRemoval` | A user removed from a team by its policy was also removed from one of the team's channels. One record is written for each channel. |

Every record includes the reason for the change: `matches-policy` for an addition, `no-longer-matches` for a removal, or `team-removal-cascade` for a channel removal that followed a team removal. The channel records that follow a team removal point back to the team removal record, so you can trace them together. See [Access control membership events](/administration-guide/comply/embedded-json-audit-log-schema#access-control-membership-events) for every field in the record.

Only membership changes are recorded. Individual permission decisions, such as whether a user may upload or download a file, aren't written to the audit log.
