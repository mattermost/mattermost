## Release v12.0 - [Major Release](https://docs.mattermost.com/product-overview/release-policy.html#release-types) \{#release-v12-0-major-release}

**Release day: 2026-10-16**

### Upgrade Impact

#### Database Schema Changes
 - Dropped the partial index ``idx_channelmembers_autotranslation_enabled`` from ``channelmembers`` non-blocking using ``CONCURRENTLY``; no downtime or query correctness impact expected.
 - Migration 000215 removed the long-deprecated ``autotranslation`` column from ``channelmembers`` via a fast catalog-only operation with no table rewrite and minimal locking impact.
 - Split the ``AttributeView`` materialized view into ``UserAttributeView`` and ``ChannelAttributeView`` for independent ABAC attribute querying; no performance impact expected as tables are feature-flagged and empty in production.
 - Increased the ``message`` column limit from 65,535 to 1,048,576 characters on ``posts``, ``drafts``, ``scheduledposts``, and ``temporaryposts``; expect a brief ``ACCESS EXCLUSIVE`` lock on each table during migration. Acquiring this lock can be delayed by active or idle-in-transaction database sessions and may temporarily block reads and writes. One deployment with approximately 12 million posts observed an upgrade delay of about 10 minutes. Actual duration depends primarily on database activity and lock contention, so large or busy deployments should test the migration and schedule a maintenance window.
 - Added new ``PostDeliveryTrackingChannels`` table with a unique index on ``ChannelId`` to support post-delivery tracking; no impact on existing tables or queries.
 - Added composite index ``idx_fileinfo_create_at_id`` on ``Fileinfo(CreateAt, Id)`` using ``CONCURRENTLY`` to improve file query performance with no downtime impact.
 - Added composite index ``idx_channels_create_at_id`` on ``Channels (CreateAt, Id)`` to accelerate cursor-based pagination; no downtime expected, minimal impact on concurrent operations.
 - Added ``DisableJoinLeaveMessages`` boolean column to ``Channels`` table to support per-channel suppression of join/leave messages; metadata-only change with no table rewrite and negligible downtime impact.
 - Added ``graph`` value to the ``property_field_type`` enum to support a new property field variant; no user tables are affected and impact on running systems is negligible.
 - Migration 000223 extracted property field options from a JSON blob in ``PropertyFields`` into new ``PropertyOptions`` and ``PropertyOptionEdges`` tables and rebuilt ``UserAttributeView`` and ``ChannelAttributeView``; deployments with large ``PropertyValues`` tables may experience brief query stalls on those views during migration.
 - Added partial composite index ``idx_propertyoptions_fieldid_createat_id`` on ``PropertyOptions(FieldID, CreateAt, ID) WHERE DeleteAt = 0`` to accelerate keyset pagination of live property options with no read/write impact.
 - Added partial composite index ``idx_propertyoptions_fieldid_name`` on ``PropertyOptions(FieldID, Name) WHERE DeleteAt = 0`` to speed up name-resolution lookups within the properties system; no downtime required.
 - Added a non-blocking composite index on ``PropertyOptionEdges (FieldID, ParentOptionID, ChildOptionID)`` to accelerate field-scoped property option hierarchy traversal with no read/write impact.
 - Backfilled ``auto_add: "always"`` metadata into ``AccessControlPolicies`` membership rules, migrating automatic-member behavior from the ``Active`` column to per-rule metadata with no performance impact.
 - Added GIN index ``idx_access_control_policies_rules`` on ``AccessControlPolicies(Data -> 'rules')`` to speed up access-control policy membership lookups with no downtime or locking impact.
 - Added a GIN index on ``AccessControlPolicies(Data -> 'imports')`` using ``jsonb_path_ops``, eliminating sequential scans on imports containment queries with no downtime or lock impact on normal traffic.

#### config.json
New setting options were added to ``config.json``. Below is a list of the additions and their default values on install. The settings can be modified in ``config.json``, or the System Console when available.
 - **Changes to All plans:**
   - Added ``DeliveryTrackingSettings.Enable`` (default ``false``) and ``DeliveryTrackingSettings.EnableForAllChannels`` (default ``true``) configuration settings to control post delivery audit logging.
   - Added ``MessageExportSettings.GlobalRelaySettings.SenderAddress`` configuration setting to optionally set a fixed From address for Global Relay EML compliance exports.
   - Added ``ServiceSettings.EnableHardenedMode`` configuration setting. The Enable Hardened Mode setting has been moved from System Console > Experimental > Features to System Console > Environment > Web Server (reported on Linux and Chromium).
   - Removed ``ImageProxySettings.RemoteImageProxyOptions`` configuration setting.
   - Removed ``ImageProxySettings.RemoteImageProxyURL`` configuration setting.
   - Removed ``EmailSettings.LoginButtonBorderColor`` configuration setting.
   - Removed ``EmailSettings.LoginButtonColor`` configuration setting.
   - Removed ``EmailSettings.LoginButtonTextColor`` configuration setting.
   - Removed ``LocalizationSettings.EnableExperimentalLocales`` configuration setting and the work-in-progress translation catalogs it exposed. Only the 22 officially supported languages are now selectable. The setting is ignored if left in an existing ``config.json``.
   - Removed the following configuration settings:
     - ``ElasticsearchSettings.BulkIndexingTimeWindowSeconds``
     - ``ClusterSettings.EnableExperimentalGossipEncryption``
     - ``ExperimentalSettings.ClientSideCertEnable``
     - ``TeamSettings.ExperimentalViewArchivedChannels``
     - ``CloudSettings.CWSMock``
     - ``PluginSettings.ChimeraOAuthProxyURL``
     - ``DataRetentionSettings.EnableBoardsDeletion``
     - ``DataRetentionSettings.BoardsRetentionDays``
     - ``SqlSettings.AtRestEncryptKey``
     - ``NativeAppSettings.EnableIntuneMAM``
     - ``GuestAccountsSettings.AllowEmailAccounts``
   - Moved the "Enable User Typing Messages" and "User Typing Timeout" settings from System Console > Experimental > Features to System Console > Site Configuration > Posts.
   - Moved the Email Batching Buffer Size, Email Batching Interval, and Use Channel Name in Email Notifications settings from System Console > Experimental > Features to System Console > Site Configuration > Notifications.
   - Moved the **Enable Account Deactivation** and **User Status Away Timeout** settings (``TeamSettings.EnableUserDeactivation`` and ``TeamSettings.UserStatusAwayTimeout``) from System Console > Experimental > Features to System Console > Site Configuration > Users and Teams.
   - Moved the **Enable Channel Viewed WebSocket Messages** setting (``ServiceSettings.EnableChannelViewedMessages``) from System Console > Experimental > Features to System Console > Environment > Web Server.
   - Moved the Enable Theme Selection, Allow Custom Themes, Default Theme, Enable Tutorial, and Enable Onboarding settings from System Console > Experimental > Features to System Console > Site Configuration > Customization. Also added ``ThemeSettings.AllowedThemes`` to System Console > Site Configuration > Customization; it was previously configurable only by editing ``config.json``.
   - Removed the ``atmos/camo`` remote image proxy type. Deployments with ``ImageProxySettings.ImageProxyType`` set to ``atmos/camo`` must update their configuration to use ``local`` or disable the image proxy before upgrading to this release.

#### Breaking Changes

<Important>

 - Dropped support for RHEL 7 and RHEL 8. The server binary now requires glibc 2.34 or later (reported on Linux).
 - Dropped support for OpenSearch 1.x. Mattermost now requires OpenSearch 2.x or newer, and logs an error on startup when connected to an unsupported version.
 - The minimum supported PostgreSQL version is now v15. PostgreSQL v14 and earlier are no longer supported.
 - The ``MoveThreadsEnabled`` feature flag is no longer supported; the server now fails to start if it is enabled. Use https://github.com/mattermost/mattermost-plugin-wrangler instead.
 - The ``AppsEnabled`` feature flag is no longer supported and must be disabled. The server now fails to start if the ``AppsEnabled`` feature flag is set to ``true``.
 - Removed the deprecated built-in Slack import API and CLI.
 - Removed deprecated Slack compatibility type aliases and functions (``SlackAttachment``, ``SlackAttachmentField``, ``ParseSlackAttachment``, ``StringifySlackFieldValue``) from the Go package. Use ``MessageAttachment``, ``MessageAttachmentField``, ``ParseMessageAttachment``, and ``StringifyMessageAttachmentFieldValue`` instead.
 - The ``POST /api/v4/logs/query`` API now returns HTTP 400 when ``date_from`` or ``date_to`` is a non-empty value that cannot be parsed with the layout ``"2006-01-02 15:04:05.999 -07:00"``. Previously such values were silently ignored and the request returned HTTP 200 with unfiltered results. Empty values continue to mean "unbounded".
 - Removed the required ``format`` query parameter from the ``GET /api/v4/license/client`` endpoint. The endpoint now returns the client license information without requiring format specification.
 - Removed the ``EnableConcurrentReact`` feature flag. The web app now always renders with concurrent React.
 - Post identity and display-override props (``from_webhook``, ``from_bot``, ``from_oauth_app``, ``from_plugin``, ``override_username``, ``override_icon_url``, ``override_icon_emoji``, ``webhook_display_name``) are no longer accepted from regular user or personal access token sessions. They are stripped on create/update and only re-applied for verified integrations (incoming webhooks and slash commands for overrides; bots/OAuth/plugins for ``from_*`` markers). Scripts that forged ``from_webhook`` and ``override_*`` via a user personal access token to post under a custom name/icon must migrate to a bot account or an incoming webhook. ``ExperimentalEnableHardenedMode`` no longer rejects reserved post props with HTTP 400; it continues to control login/MFA/password-reset/5xx scrubbing only.
 - Removed deprecated interactive dialog date/datetime fields. Top-level ``min_date``, ``max_date``, and ``time_interval``, and ``datetime_config.allow_manual_time_entry``, are no longer accepted; use ``datetime_config`` (with ``manual_time_entry``) instead. Legacy keys are silently ignored.
 - Auto-adding members to a channel or team with an attribute-based access policy is now stored on the policy's membership rule instead of the policy's active flag, and is set per channel and per team. Existing settings are migrated automatically. Clients using ``PUT /api/v4/access_control_policies`` to set the ``active`` field to control auto-adding must set the membership rule's ``auto_add`` metadata instead; the ``/access_control_policies/activate`` endpoint continues to work unchanged (reported on webapp).
 - Several pre-packaged plugins received major version updates in this release because they required changes to run on v12.0 without errors. Web app plugins that have not been rebuilt for v12.0 may have their activation suppressed to prevent runtime errors. Before upgrading, update community-built plugins to a release that supports v12.0, and rebuild and test any self-built plugins against v12.0. See [important upgrade notes](https://docs.mattermost.com/administration-guide/upgrade/important-upgrade-notes.html) for details.
 - A custom attribute field with more than 1000 options now serializes a count in place of its option list.
 - Removed the ``EmailLoginButtonColor``, ``EmailLoginButtonBorderColor``, and ``EmailLoginButtonTextColor`` client configuration fields alongside the ``EmailSettings`` login button color settings. These fields were never applied by any client.

</Important>

#### Compatibility
 - Updated the minimum supported macOS version to 15+ and the minimum supported Safari version to 27+. Earlier versions are no longer supported for the desktop and web apps. See the [software and hardware requirements](https://docs.mattermost.com/deployment-guide/software-hardware-requirements.html) documentation for details.

### Improvements

See [this blog post](https://mattermost.com/blog/mattermost-v12-0-is-now-available/) on the highlights in our latest release.

#### User Interface
 - Pre-packaged Calls plugin version [v1.12.5](https://github.com/mattermost/mattermost-plugin-calls/releases/tag/v1.12.5).
 - Pre-packaged Dataminr plugin version [v2.0.0](https://github.com/mattermost/mattermost-plugin-dataminr/releases/tag/v2.0.0).
 - Pre-packaged GitLab plugin version [v2.0.0](https://github.com/mattermost/mattermost-plugin-gitlab/releases/tag/v2.0.0).
 - Pre-packaged Zoom plugin version [v2.0.0](https://github.com/mattermost/mattermost-plugin-zoom/releases/tag/v2.0.0).
 - Updated the web app to React 19 with concurrent rendering enabled by default (reported on webapp).
 - Added copy buttons for newly generated personal access tokens and bot access tokens.
 - Added accessible labels to hide and show OpenGraph image previews.
 - Added two new interactive dialog element types: ``checkbox_group`` (a multi-select list of checkboxes) and ``checkbox_matrix`` (a grid of checkboxes with configurable rows, columns, and single- or multi-select per row). Both support a new ``label_position`` option, which is also available for radio and bool elements.
 - Increased the maximum length of an interactive dialog's title from 24 to 80 characters (reported on webapp and mobile app).
 - Capped single image previews in posts at 700px wide to match the design spec.
 - Updated display settings to fall back to English when the configured locale was unavailable.
 - Added an ``IMPORTED - INACTIVE`` tag to user profiles to identify accounts created by a scoped migration pending admin review.
 - Channel admins can now hide join/leave system messages per channel via Channel Settings > Configuration. Posts are stored and reappear if the setting is re-enabled.
 - Improved channel attribute chips in the channel header and thread right-hand sidebar, and polished the System Console attributes user interface.

#### Plugins/Integrations
 - Added plugin hook ``OnLicenseChanged``, invoked when the server license changes.
 - Added a Plugin API method for session-scoped file action policy checks.
 - Added request deadline and cancellation propagation for server-to-plugin and inter-plugin HTTP requests made by context-aware plugins.
 - Added shared React JSX runtime exports for web app plugins, including support for development JSX on production hosts (reported on webapp).
 - Added support for licensed add-ons: plugins that are purchased alongside a Mattermost license and only run when the license grants them.
 - Plugin-owned Global Attributes now render as a read-only Definition/Applies-to page instead of redirecting away, with a link to the owning plugin's settings.
 - Updated the React Bootstrap library exposed by the web app to support future React upgrades.

#### Administration
 - Admins can now grant delegated (granular) administration roles directly from System Console > Users > Manage Roles modal.
 - Added the ability for System Console admins to upload or remove a user's profile picture from the User Management user detail page.
 - Added the ability to delete a Global Attribute from the Manage Attributes page in the System Console.
 - Added a duplicate plugin upload confirmation modal that compares the installed plugin version with the uploaded plugin version before overwrite confirmation.
 - Replaced the plugin settings page enable setting with immediate plugin action buttons, and added an uninstall option from plugin settings.
 - Improved plugin upload UX in the System Console with an automatic upload dropzone, progress indicator, and clearer disabled-state messaging.
 - Added stricter server config validation for export, SQL replica monitor, feature flag sync, burn-on-read, LDAP group filter, Elasticsearch index sizing, connected workspace batch size, push notification buffer, log level, file storage, email, session, data retention, TLS, and webserver settings.
 - Added audit logging for new events caused by cached data deletion on mobile devices related to Mobile Ephemeral Mode settings (reported on mobile app).
 - Access rules can now compare a user's attributes with attributes of the channel being accessed, including ``hasAnyOf`` and ``hasAllOf`` for multi-value attributes, behind the new ``ResourceAttributesInPolicies`` feature flag. A rule that references a channel attribute denies access for every channel that has not set a value for it.
 - Added four access policy functions for comparing graph custom attributes: ``coversAll``, ``coversAny``, ``withinAll``, and ``withinAny``.
 - Extended personal access token lifetime enforcement, expiry notifications, and non-compliant token revocation to user-owned bot accounts. Plugin-owned and protected system bot accounts remain exempt.
 - Added webapp support for personal access token expiry and regeneration on user-owned bot accounts.
 - Added a new ``graph`` custom attribute type whose options form a hierarchy, gated by the ``PropertyFieldGraph`` feature flag (off by default). Values are shown as option names and set with an option picker on the profile and System Console user detail pages. Added REST endpoints and plugin API methods to list, create, update, and delete a custom attribute's options.
 - Added a new Hierarchical attribute type in the Global Attributes management screen in the System Console.
 - Existing Custom Profile Attributes (User Attributes) fields are now automatically migrated into Global Attributes templates on server startup. The legacy "User Attributes" admin console page has been removed.
 - System Console Manage Attributes now opens existing managed attributes for edit. Saving PATCHes the attribute definition and applies add/remove changes in the same action, including deleting a resource application and its stored values when that resource is removed.
 - Moved the New attribute button on the Attribute Management listing page into the page header and removed the Duplicate attribute action from the row menu.
 - Applied channel file download permission policies to content reviewers.
 - Added a live Security Updates bulletin to the Security Guide that filters advisories by product, severity, issue ID, date, and affected version range.
 - Hid the System Console Recaps page unless the ``EnableAIRecaps`` feature flag is enabled.
 - Updated OAuth application management and authorization endpoint handling.

#### mmctl
 - Added ``--expires-in`` flag to ``mmctl bot create --with-token`` for personal access token lifetime enforcement on user-owned bot accounts.
 - Added ``--team-name`` and ``--team-id`` flags to ``mmctl export create`` to export a single team or a comma-separated list of teams instead of the full server.
 - Added ``--channel-name`` and ``--channel-id`` flags to ``mmctl export create`` to export a single channel or a comma-separated list of channels from a team.
 - Scoped exports from ``mmctl export create`` omit custom emoji by default to avoid pulling the source server's entire emoji library into the destination. Pass ``--include-custom-emoji`` to include them; reactions referencing custom emoji absent from the destination will render as literal ``:name:`` text otherwise.
 - Custom permission schemes assigned to exported teams are now preserved in the export.
 - Added ``--destination-team-name`` and ``--destination-team-id`` flags to ``mmctl import process`` to remap the exported team to a different team on the destination.
 - Added ``--destination-channel-name`` and ``--destination-channel-id`` flags to ``mmctl import process`` to remap the exported channel to a different channel on the destination.
 - Added ``--skip-preflight`` flag to ``mmctl import process`` to bypass the LDAP/SAML configuration check that runs before importing SSO users.
 - Import jobs now checkpoint progress and can be resumed after a crash or failure, including jobs interrupted by a hard process kill.
 - All users brought over by a scoped import land deactivated and tagged ``IMPORTED - INACTIVE`` pending admin review. Users who already exist on the destination are matched to their existing account and remain active.
 - When an imported user's username matches an existing destination account, their posts and reactions are attributed to that account instead of being dropped.
 - Posts referencing a channel that does not exist on the destination are skipped instead of aborting the entire import.
 - A role update that would demote the destination's only system admin is skipped instead of aborting the import.
 - A source user's historical deactivation date is preserved rather than overwritten with the import timestamp.

#### Performance
 - Improved performance of the bulk-indexing job for Elasticsearch and Opensearch for very large ``FileInfo`` and ``Channels`` tables.
 - Reduced database load by caching lookups of non-existent custom emoji names (e.g. emoji-like tokens in timestamps such as "11:11:11").

### Bug Fixes
 - Fixed an issue where link previews could render for restricted domains after following redirect chains.
 - Fixed an issue where Direct Message and Group Message channels in the sidebar could render as blank rows or show a member count of zero until a channel was clicked.
 - Fixed an issue where inline images and videos could flicker between two sizes when a media gallery was near the width at which a scrollbar appears.
 - Fixed an issue with output formatting in ``mmctl``.
 - Fixed an issue with bulk import handling for existing accounts.
 - Fixed the channel member API endpoints returning an invalid ``last_viewed_at`` and ``last_update_at`` value of ``-1`` for other users' memberships. These fields are now omitted from the response when they belong to a user other than the requester (reported on Linux).
 - Fixed ABAC plugin policy saves to enforce self-inclusion and shared write guards, and hardened the policy editor/test user interface against null users and incomplete fields.
 - Fixed rendering, navigation, validation, and search for section-based plugin settings.
 - Fixed an issue where a disabled plugin with multiple custom settings sections and mixed ``fallback`` values hid the settings of fallback-enabled sections behind a single "enable the plugin" warning.
 - Fixed an issue where a running plugin's settings could render read-only in the System Console when the plugin defined its settings using sections without a footer.
 - Fixed an issue where the App Marketplace modal changed width when paging between plugin lists.
 - Fixed an issue where the System Console Recaps page was hidden from system admins on upgraded servers because the AI Recaps sysconsole permissions were never applied to the ``system_admin`` role.
 - Fixed a server startup crash where an app migration could read a row it had just written from a read replica that had not yet caught up, aborting startup. This affected servers that are both licensed and have ``SqlSettings.DataSourceReplicas`` configured.
 - Fixed a bug where migrating a select, multiselect, or rank Custom Profile Attribute field into a Global Attributes template could leave the field with every option duplicated.
 - Fixed an issue where ``ServiceSettings.OutgoingIntegrationRequestsTimeout`` values above 30 seconds were silently capped at 30 seconds for slash commands, outgoing webhooks, post action callbacks, interactive dialog submissions, and dialog lookups.
 - Fixed an issue where plugins implementing the ``ScheduledPostWillBeCreated`` hook received the content of burn-on-read messages when they were scheduled or edited. The hook is now skipped for burn-on-read scheduled posts, so guard plugins can no longer inspect or reject them.
 - Fixed an issue where plugin right-hand sidebar panels, such as Copilot, could not be opened from the App Bar while viewing the Threads view.
 - Prevented plugin startup failures from blocking web app startup. Failed plugins remained disabled until the page was reloaded (reported on webapp).
 - Fixed an issue in which built-in properties were not displayed in the alert banner for teams and channels whose memberships are managed by an attribute-based access control policy.
 - Fixed an issue where interactive dialogs submitted against the wrong channel. Dialogs now correctly submit against the channel the trigger was created in, regardless of which channel the user is currently viewing (reported on webapp).
 - Fixed an issue where posts older than ``ServiceSettings.PostEditTimeLimit`` could not be pinned or unpinned.
 - Fixed a bug where clicking a user mention in the message preview posted the draft instead of opening the profile popover.
 - Fixed an issue where the schedule message menu stayed open after selecting a time on mobile web, which allowed the same draft to be scheduled more than once (reported on webapp and mobile web).
 - Fixed an issue where the Default Appearance of Image Previews display setting did not apply to GIFs posted from the GIF picker that arrived in an already-open channel.
 - Fixed an issue where the Korean nori analyzer was never applied when the search cluster reported the plugin under a prefixed component name, such as ``opensearch-analysis-nori`` on AWS OpenSearch Service.
 - Fixed System Console settings that accept a comma-separated list, such as Allowed Themes and DCR Redirect URI Allowlist, saving entries with the surrounding whitespace included.
 - Fixed an issue where the user interface let an admin attempt to change the default channel's URL, which the server always rejects. The URL is now shown as read-only with an explanation, while the channel name remains editable.
 - Fixed an issue where a CSV export from System Console > User Management > Users ignored the search term and exported all users instead of the filtered subset shown in the user interface.
 - Fixed an issue where the System Console header menu's scroll bar was clipped by the sidebar when the administrator belonged to enough teams for the menu to overflow (reported on desktop app).
 - Fixed the cloud preview introduction modal so it is vertically centered instead of sitting at the bottom of the page.
 - Fixed the guest invitation error shown when the invitee is already a workspace member: inviters who cannot add members to the team are now directed to contact a system administrator instead of being told to invite the person as a member (reported on webapp).
 - Fixed four admin console strings that built English grammar in code and could not be translated correctly, including a tooltip that rendered a stray English "a" or "an" in every other language.
 - Corrected English translation typos and fixed audit-log wording for users removed from channels.
 - Fixed an issue with user profile update handling.
