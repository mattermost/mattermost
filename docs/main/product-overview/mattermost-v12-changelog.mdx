## Release v12.1 - [Feature Release](https://docs.mattermost.com/product-overview/release-policy.html#release-types) \{#release-v12-1-feature-release}

**Release day: 2026-11-16**

### Upgrade Impact

#### Database Schema Changes
  - Added the ``creator`` value to the ``permission_level`` enum type to support the new creator permission level for property fields; an enum value addition with no table rewrite and negligible impact on running systems.
  - Added the ``healthfindings`` table, which stores the findings raised by the Built-in Health Dashboard keyed by a finding fingerprint; a new table with no impact on existing tables or queries.
  - Added the index ``idx_healthfindings_lastseenat`` on ``healthfindings (lastseenat)`` using ``CONCURRENTLY``, so the build doesn't block reads or writes; no downtime expected.
  - Added the partial index ``idx_propertyvalues_groupid_fieldid`` on ``PropertyValues (GroupID, FieldID)`` for rows where ``DeleteAt`` is 0, using ``CONCURRENTLY``, to speed up lookups that filter by group and field; no downtime expected.

#### config.json
New setting options were added to ``config.json``. Below is a list of the additions and their default values on install. The settings can be modified in ``config.json``, or the System Console when available.
  - **Changes to All plans:**
    - Under ``ElasticsearchSettings`` in ``config.json``, added ``EnableFileIndexing`` configuration setting to control indexing of file attachments in Elasticsearch and OpenSearch.

#### Compatibility
  - Updated minimum supported Firefox version to 153+.

### Improvements

See [this blog post](https://mattermost.com/blog/mattermost-v12-1-is-now-available/) on the highlights in our latest release.

#### User Interface
  - Mattermost Calls was updated to v1.12.6. Fixed layout regressions in call menus and the Desktop screen share picker, and the self video thumbnail now shows on the left in 1:1 video calls.
  - Deprecated the ServiceNow plugin. It is no longer prepackaged with the server and is no longer offered in the onboarding wizard.
  - Improved System Console Sidebar Navigation user interface.
  - Updated ``ConfirmModal`` to use Compass UI buttons.
  - Added an Out of Office notice above the Direct Message composer when the recipient has automatic replies enabled, and suppressed the off-hours indicator while that notice is shown.
  - Themed the full-page error screen, including Post Not Found, with the signed-in user's center channel and link colors.
  - Added support for Markdown images, Markdown paste, and caret-anchored autocomplete in the rich text editor, and fixed rich text editor formatting so the composer matches posted messages.
  - "Download all" in the media gallery now downloads all attachments as a single zip file instead of one download per file.
  - Markdown phone links now render as a phone pills component.
  - Introduced a new reusable call options menu component that allows users to start either a Mattermost call or dial a user's phone number for the Calls plugin.
  - Made the system policy indicator banner fully translatable as complete sentences, with locale-aware formatting of policy name lists.
  - Added a "Managed by" indicator to the Applies to > Users card of a Global Attribute synced from AD/LDAP or SAML, showing the sync source and that the values are not editable in Mattermost.
  - Added attributes to bot accounts: bot managers can set a bot's attribute values from the Add/Edit Bot page, and the bot's profile popover shows them.
  - Prevented burn-on-read messages from being scheduled as weekly recurring posts.
  - Added the Enable File Search setting to the System Console. When file search is disabled, the web app now hides file search and channel files instead of showing empty results.
  - Clarified the wording of several System Console messages on the Site health page and in user attribute sync settings.
  - The auto-translation AI Service setting in the System Console now shows when the saved service no longer exists in the Agents plugin, instead of displaying a different service as selected.

#### Plugins/Integrations
  - Added the ``pluginapi/testhelper`` package to the public module, enabling plugin authors to write integration tests using real Mattermost containers via testcontainers-go.

#### Administration
  - Added the Built-in Health Dashboard rule evaluation engine in ``platform/shared/healthcheck``, including deployment gating, panic containment, and deterministic finding fingerprinting.
  - Added the ``EnforceLogPathRoot`` feature flag, disabled by default. When enabled, a log or audit file path that resolves outside the logging root (``MM_LOG_PATH``, or the default logs directory) causes the server to refuse to start and is rejected on configuration save, instead of only being logged as an error. Validation now also covers ``LogSettings.FileLocation`` and ``ExperimentalAuditSettings.FileName``.
  - Support packet ``stats.yaml`` now omits failed stat keys instead of serializing them as zero, preserving unknown-vs-zero semantics in packet data.
  - Support packet generation now accumulates and reports all diagnostics, job, and permission collector errors in ``warning.txt`` instead of potentially overwriting earlier errors.
  - Support packet ``diagnostics.yaml`` now omits a field when collecting it fails, instead of reporting it as 0 or empty. This covers the hostname, total memory, file descriptor counts, database type, version and schema version, database connection pool counters, file store disk space and filesystem type, and the cluster node count. A standalone server without a cluster interface now reports ``number_of_nodes`` as 1 instead of 0.
  - Unhandled promise rejections in the web app are now logged to the server, and are shown in the error bar when Developer Mode is enabled.
  - AD/LDAP and SAML can now sync select and multiselect user attributes. Values from the identity provider are added as options automatically, and options no user holds are removed. An attribute that the identity provider stops sending now clears the user's synced value at the next sync or login instead of keeping the previous value. Only the sync can add, rename, or remove the options of a synced attribute. An attribute linked to both AD/LDAP and SAML is now synced from AD/LDAP only.
  - Added a new Attribute-Based Access Control (ABAC) permission, Create Burn-on-Read Message, so administrators can restrict which users are able to send burn-on-read messages.
  - Added a new "creator" permission level for property fields. It grants the creator of the target object the same access that the "admin" level grants, in addition to everyone the "admin" level already covers.
  - Added ``ElasticsearchSettings.EnableFileIndexing`` configuration setting to stop indexing file attachments in Elasticsearch and OpenSearch.
  - Added bundled product documentation at ``/_documentation`` (root-path installs) and a ``mattermost docs`` CLI to serve it locally when the server is down. SiteURL subpath installs should use ``mattermost docs`` only.
  - Offered the TLS 1.3 hybrid key exchange X25519MLKEM768 when Mattermost terminates TLS.

#### mmctl
  - Fixed an issue where ``mmctl config set`` could not set a list setting, such as ``SqlSettings.DataSourceReplicas``, to exactly one value.

#### Performance
  - Added the ``EnforceLogPathRoot`` feature flag to reject log and audit file paths that resolve outside the logging root, preventing unintended filesystem access.

### Bug Fixes
  - Fixed an issue where multi-byte (CJK) characters were dropped, doubled, or split when typing quickly in the AI Agent rewrite prompt.
  - Fixed an issue where the quick switcher ("Find Channels") ranked Group Messages containing a person above the Direct Message with that person when typing their username.
  - Fixed an issue where server log downloads and support packet log collection failed when the log directory is reached through a symlink. Log paths whose final component is an unresolved symlink are now rejected.
  - Fixed an issue where SVG files with relative dimensions, such as ``width="100%"``, or a comma-separated ``viewBox`` were previewed at the wrong size or not at all.
  - Fixed an issue where the message composer's remove-labels control was invisible while keyboard-focused, and added a tooltip for it on hover and focus.
  - Fixed an issue where the channel autocomplete in the invite modal used different row spacing and channel-slug formatting than the channel autocomplete in the post composer.
  - Fixed an issue where a slash command whose integration replied with a 2xx status other than 200 OK, such as 201 Created, showed an error to the user instead of the integration's response.
  - Fixed an issue where choosing Manage roles > Member for a guest in the System Console left their team and channel memberships as Guest. Manage roles is no longer offered for guests; use Promote to member instead.
  - Fixed an issue where the dropdown chevron on hierarchical attribute value pickers shrank as more values were selected and the input wrapped onto multiple lines.
  - Fixed an issue where searching for a number on its own did not find posts containing that number as the trailing part of a hyphenated word, such as searching "12345" not finding "flight-12345", when PostgreSQL is the search backend.
  - Fixed an issue where editing or deleting a post immediately after posting it could intermittently fail on servers configured with database read replicas.
  - Fixed an issue where the Channel Settings modal blocked navigation to its other sections while a channel permission rule was being edited without explaining why.
  - Fixed an issue where a draft sent from the Drafts panel could reappear after switching teams or reloading.
  - Fixed an issue where the OpenSearch bulk indexing job could hang indefinitely when a connection to OpenSearch stalled.
  - Fixed an issue where ``/secure-connection remove`` reported that the connection was not found when deleting it failed, instead of showing the error.
  - Fixed an issue where ``/secure-connection remove`` reported a connection as not found when ``connectionID`` was empty or malformed. It now replies that the argument is missing or invalid.
  - Fixed an issue where ``/secure-connection create`` showed internal error details instead of a translated error message when creating a secure connection failed.
  - Fixed an issue where the High Availability config hash reported in the System Console showed each node's boot-time value instead of its current configuration, which could indicate a config mismatch between nodes that were running identical configs.
  - Fixed an issue where only the first ten system permission policies were enforced, so any policy beyond that — including one that should have denied access — was silently ignored.
  - Fixed an issue where message attachment fields with a title but an empty value were not displayed when Mattermost Blocks was enabled.

### API Changes
  - Added an optional ``includePropertyGroups`` query parameter to ``GET /api/v4/posts/{post_id}``, ``GET /api/v4/posts/{post_id}/thread``, ``GET /api/v4/channels/{channel_id}/posts``, ``GET /api/v4/users/{user_id}/channels/{channel_id}/posts/unread``, and ``GET /api/v4/channels/{channel_id}/views/{view_id}/posts``, which hydrates each post's property values for the named group onto post metadata.
  - Added ``DELETE /{fingerprint:[a-f0-9]{32}}/mute`` (``unmuteHealthFinding``) API endpoint.
  - Added ``GET /`` (``getHealthFindings``) API endpoint.
  - Added ``POST /{fingerprint:[a-f0-9]{32}}/mute`` (``muteHealthFinding``) API endpoint.

### Audit Log Event Changes

  - Added ``AuditEventUnmuteHealthFinding`` audit log event.

## Release v12.0 - [Major Release](https://docs.mattermost.com/product-overview/release-policy.html#release-types) \{#release-v12-0-major-release}

**Release day: 2026-10-16**

<Important>

**Breaking Changes**
 - This release includes a database migration that increases the maximum message length from 16,383 to 262,144 characters by widening the ``message`` column from ``VARCHAR(65535)`` to ``VARCHAR(1048576)``. The message limit is a quarter of the column size, to allow for characters of up to four bytes. Widening ``VARCHAR`` is metadata-only on supported PostgreSQL versions, but the migration still takes a brief ``ACCESS EXCLUSIVE`` lock on each affected table, including ``posts``. Acquiring this lock can be delayed by active or idle-in-transaction database sessions, and reads and writes on the table wait while it is pending. To keep the lock short, the full-text index on post messages (``idx_posts_message_txt``) is dropped before the column is widened and rebuilt concurrently by a later migration, so database full-text search of posts runs without that index until the rebuild completes. Large or busy deployments should test the migration and schedule a maintenance window.
 - Several pre-packaged plugins received major version updates in v12.0 because they required changes to run on this release without errors. Web app plugins that have not been rebuilt for v12.0 may have their activation suppressed to prevent runtime errors. Before upgrading, update community-built plugins to a release that supports v12.0, and rebuild and test any self-built plugins against v12.0. See the React 19 note in this section for the APIs removed in that version and the codemod for updating a plugin.
 - Dropped support for RHEL 7 and RHEL 8. The server binary now requires glibc 2.34 or later (reported on Linux).
 - Dropped support for OpenSearch 1.x. Mattermost now requires OpenSearch 2.x or newer, and logs an error on startup when connected to an unsupported version.
 - ``atmos/camo`` is no longer supported as an image proxy. If ``ImageProxySettings.ImageProxyType`` is set to ``atmos/camo``, the server automatically changes it to ``local`` on startup and logs a warning. If image proxying is enabled, images are then proxied by the Mattermost server itself instead of the external ``atmos/camo`` service, so the server must be able to reach the external hosts that images are loaded from. The ``RemoteImageProxyURL`` and ``RemoteImageProxyOptions`` settings have also been removed and are ignored.
 - The minimum supported PostgreSQL version is now v15. PostgreSQL v14 and earlier are no longer supported.
 - The ``MoveThreadsEnabled`` feature flag is no longer supported. If it is enabled, the server turns it off on startup and logs a warning. Use https://github.com/mattermost/mattermost-plugin-wrangler instead.
 - The ``AppsEnabled`` feature flag is no longer supported. If it is set to ``true``, the server turns it off on startup and logs a warning.
 - Removed the deprecated built-in Slack import API and CLI. The ``POST /teams/{team_id}/import`` endpoint and the ``mattermost import slack`` command are no longer available. Use the [mmetl tool with ``mmctl import``](https://docs.mattermost.com/administration-guide/onboard/migrate-from-slack.html) instead.
 - Removed deprecated Slack compatibility type aliases and functions (``SlackAttachment``, ``SlackAttachmentField``, ``ParseSlackAttachment``, ``StringifySlackFieldValue``) from the Go package. Use ``MessageAttachment``, ``MessageAttachmentField``, ``ParseMessageAttachment``, and ``StringifyMessageAttachmentFieldValue`` instead.
 - The ``POST /api/v4/logs/query`` API now returns HTTP 400 when ``date_from`` or ``date_to`` is a non-empty value that cannot be parsed with the layout ``"2006-01-02 15:04:05.999 -07:00"``. Previously such values were silently ignored and the request returned HTTP 200 with unfiltered results. Empty values continue to mean "unbounded".
 - Removed the required ``format`` query parameter from the ``GET /api/v4/license/client`` endpoint. The endpoint now returns the client license information without requiring format specification.
 - Removed the ``EnableConcurrentReact`` feature flag. The web app now always renders with concurrent React.
 - Post identity and display-override props (``from_webhook``, ``from_bot``, ``from_oauth_app``, ``from_plugin``, ``override_username``, ``override_icon_url``, ``override_icon_emoji``, ``webhook_display_name``) are no longer accepted from regular user or personal access token sessions. They are stripped on create/update and only re-applied for verified integrations (incoming webhooks and slash commands for overrides; bots/OAuth/plugins for ``from_*`` markers). Scripts that forged ``from_webhook`` and ``override_*`` via a user personal access token to post under a custom name/icon must migrate to a bot account or an incoming webhook. ``EnableHardenedMode`` no longer rejects reserved post props with HTTP 400; it continues to control login/MFA/password-reset/5xx scrubbing only.
 - Removed deprecated interactive dialog date/datetime fields. Top-level ``min_date``, ``max_date``, and ``time_interval``, and ``datetime_config.allow_manual_time_entry``, are no longer accepted; use ``datetime_config`` (with ``manual_time_entry``) instead. Legacy keys are silently ignored.
 - Auto-adding members to a channel or team with an attribute-based access policy is now stored on the policy's membership rule instead of the policy's active flag, and is set per channel and per team. Existing settings are migrated automatically. Clients using ``PUT /api/v4/access_control_policies`` to set the ``active`` field to control auto-adding must set the membership rule's ``auto_add`` metadata instead; the ``/access_control_policies/activate`` endpoint continues to work unchanged (reported on webapp).
 - A custom attribute field with more than 1000 options now serializes a count in place of its option list.
 - Removed the ``EmailLoginButtonColor``, ``EmailLoginButtonBorderColor``, and ``EmailLoginButtonTextColor`` client configuration fields alongside the ``EmailSettings`` login button color settings. These fields were never applied by any client.
 - The channel member API endpoints no longer return ``last_viewed_at`` and ``last_update_at`` for other users' memberships. They previously returned an invalid value of ``-1``; the fields are now omitted from the response entirely when they belong to a user other than the requester. Clients reading those fields for other users must handle their absence (reported on Linux).
 - A set of unused configuration settings has been removed: ``ElasticsearchSettings.BulkIndexingTimeWindowSeconds``, ``ClusterSettings.EnableExperimentalGossipEncryption``, ``ExperimentalSettings.ClientSideCertEnable``, ``TeamSettings.ExperimentalViewArchivedChannels``, ``CloudSettings.CWSMock``, ``PluginSettings.ChimeraOAuthProxyURL``, ``DataRetentionSettings.EnableBoardsDeletion``, ``DataRetentionSettings.BoardsRetentionDays``, ``SqlSettings.AtRestEncryptKey``, ``NativeAppSettings.EnableIntuneMAM``, and ``GuestAccountsSettings.AllowEmailAccounts``. Removed fields present in an existing ``config.json`` are ignored and the server starts normally, so no configuration changes are required. Admins using ``NativeAppSettings.EnableIntuneMAM`` should use ``IntuneSettings.Enable`` instead.
 - The Mattermost web and desktop apps are built on [React 19](https://react.dev/blog/2024/04/25/react-19-upgrade-guide). Only plugins that register web app (frontend) components are affected; server-only plugins are unaffected. Web app plugins use the React version provided by the web app, so their components render under React 19 whether or not they are rebuilt. Plugins calling APIs removed in React 19 (``ReactDOM.findDOMNode``, ``propTypes``/``defaultProps`` on function components, legacy Context, string refs), or depending on legacy synchronous rendering, may break. Run ``npx codemod@latest react/19/migration-recipe`` against affected plugins and correct any removed-API usage. See the [forum post](https://forum.mattermost.com/t/starting-with-mattermost-v12-0-october-2026-the-mattermost-web-and-desktop-apps-are-built-on-react-19/26038) for full details.
 - Removed the **System Console > System Attributes > User Attributes** page on Enterprise plans. Existing Custom Profile Attributes (User Attributes) fields are migrated automatically into **Attribute Management** on server startup and are managed there from v12.0. The old page's URL redirects to Attribute Management.
 - ``PATCH`` and ``DELETE`` requests to ``/api/v4/custom_profile_attributes/fields/{field_id}`` now return HTTP 400 when the field is linked to an Attribute Management template, with an error pointing to the Global Attributes API. On Enterprise plans, eligible existing User Attributes fields are linked to templates automatically on server startup, so scripts and integrations that edit or delete these fields through the User Attributes API must use the Global Attributes API instead.
 - The ``LocalizationSettings.EnableExperimentalLocales`` configuration setting has been removed, along with most of the work-in-progress translation catalogs it exposed. Danish is now a supported language, and Czech, Croatian, Finnish, Lithuanian, Norwegian Bokmål and Portuguese (Portugal) are available to all users as experimental languages without the setting. Users who had selected any other removed language see Mattermost in English. The setting is ignored if left in an existing ``config.json``.
 - Removed the Belarusian language. Users who had Belarusian selected now see the default language.
 - ``ServiceSettings.ExperimentalEnableHardenedMode`` is deprecated and replaced by ``ServiceSettings.EnableHardenedMode``, which has moved from **System Console > Experimental > Features** to **System Console > Environment > Web Server**. An existing value is carried over to ``EnableHardenedMode`` automatically on upgrade. After that, the server reads only ``EnableHardenedMode``, so update any configuration management, environment variables, or scripts that still set the old setting.

</Important>

### Upgrade Impact

#### Database Schema Changes
 - Dropped the partial index ``idx_channelmembers_autotranslation_enabled`` from ``channelmembers`` non-blocking using ``CONCURRENTLY``; no downtime or query correctness impact expected.
 - Migration 000215 removed the long-deprecated ``autotranslation`` column from ``channelmembers`` via a fast catalog-only operation with no table rewrite and minimal locking impact.
 - Split the ``AttributeView`` materialized view into ``UserAttributeView`` and ``ChannelAttributeView`` for independent ABAC attribute querying; no performance impact expected as tables are feature-flagged and empty in production.
 - Increased the ``message`` column limit from 65,535 to 1,048,576 characters on ``posts``, ``drafts``, ``scheduledposts``, and ``temporaryposts``, which raises the maximum message length from 16,383 to 262,144 characters; expect a brief ``ACCESS EXCLUSIVE`` lock on each table during migration. Acquiring this lock can be delayed by active or idle-in-transaction database sessions and may temporarily block reads and writes. The full-text index ``idx_posts_message_txt`` is dropped before ``posts.message`` is widened, so that Postgres does not rebuild it while holding the lock.
 - Migration 000234 recreates the full-text index ``idx_posts_message_txt`` on ``posts`` using ``CREATE INDEX CONCURRENTLY``, without blocking reads or writes. Database full-text search of posts runs without the index until the build completes.
 - Added new ``PostDeliveryTrackingChannels`` table with a unique index on ``ChannelId`` to support post-delivery tracking; no impact on existing tables or queries.
 - Added composite index ``idx_fileinfo_create_at_id`` on ``Fileinfo(CreateAt, Id)`` using ``CONCURRENTLY`` to improve file query performance with no downtime impact.
 - Added composite index ``idx_channels_create_at_id`` on ``Channels (CreateAt, Id)`` to accelerate cursor-based pagination; no downtime expected, minimal impact on concurrent operations.
 - Added ``DisableJoinLeaveMessages`` boolean column to ``Channels`` table to support per-channel suppression of join/leave messages; metadata-only change with no table rewrite and negligible downtime impact.
 - Added ``graph`` value to the ``property_field_type`` enum to support a new property field variant; no user tables are affected and impact on running systems is negligible.
 - Migration 000223 extracted property field options from a JSON blob in ``PropertyFields`` into new ``PropertyOptions`` and ``PropertyOptionEdges`` tables and rebuilt ``UserAttributeView`` and ``ChannelAttributeView``; deployments with large ``PropertyValues`` tables may experience brief query stalls on those views during migration.
 - Added partial composite index ``idx_propertyoptions_fieldid_createat_id`` on ``PropertyOptions(FieldID, CreateAt, ID) WHERE DeleteAt = 0`` to accelerate keyset pagination of live property options with no read/write impact.
 - Added partial composite index ``idx_propertyoptions_fieldid_name`` on ``PropertyOptions(FieldID, Name) WHERE DeleteAt = 0`` to speed up name-resolution lookups within the properties system; no downtime required.
 - Added a non-blocking composite index on ``PropertyOptionEdges (FieldID, ParentOptionID, ChildOptionID)`` to accelerate field-scoped property option hierarchy traversal with no read/write impact.
 - Backfilled ``auto_add: "always"`` metadata into ``AccessControlPolicies`` membership rules, migrating automatic-member behavior from the ``Active`` column to per-rule metadata with no performance impact.
 - Added GIN index ``idx_access_control_policies_rules`` on ``AccessControlPolicies(Data -> 'rules')`` to speed up access-control policy membership lookups with no downtime or locking impact.
 - Added a GIN index on ``AccessControlPolicies(Data -> 'imports')`` using ``jsonb_path_ops``, eliminating sequential scans on imports containment queries with no downtime or lock impact on normal traffic.
 - Removed stale ``ldap`` and ``saml`` keys from the ``Attrs JSONB`` column in ``PropertyFields`` for all non-user, non-template rows; irreversible data cleanup with no expected downtime but potential full-table scan on unindexed deployments.
 - Added GIN full-text ``index idx_posts_message_txt`` on ``posts(message)`` using ``CREATE INDEX CONCURRENTLY``; large deployments should expect an extended, I/O-intensive build with no downtime.

#### Administration
 - Admins can now grant delegated (granular) administration roles directly from System Console > Users > Manage Roles modal.
 - Added the ability for System Console admins to upload or remove a user's profile picture from the User Management user detail page.
 - Added the [Attribute Management](https://docs.mattermost.com/administration-guide/manage/admin/attribute-management) page under **System Console > System Attributes** (Enterprise plans) for defining an attribute once and applying it to users, to channels on Enterprise Advanced when the ``ChannelAttributes`` feature flag is enabled, and to posts when the ``PostAttributes`` feature flag is enabled. Attributes can be Text, Phone, URL, Select, Multiselect, or Ranked. Admins can create, edit, and delete attributes, and renaming an attribute also renames the linked resource fields that still share its label. Attributes owned by a plugin are shown read-only, with a link to the plugin's settings.
 - Added a Hierarchical attribute type (``graph`` in the API) whose values form a parent/child hierarchy. Hierarchical attributes are created in Attribute Management, set with an option picker in Account Settings and on the System Console user detail page, and shown by name in the user profile popover. An existing attribute's type cannot be changed to or from Hierarchical. Access policies can compare Hierarchical attributes with four new functions: ``coversAll``, ``coversAny``, ``withinAll``, and ``withinAny``. Added REST endpoints and plugin API methods to list, create, update, and delete an attribute's options.
 - Added [channel attributes](https://docs.mattermost.com/administration-guide/manage/admin/channel-attributes) on Enterprise Advanced, behind the ``ChannelAttributes`` feature flag. When creating a channel, users are asked for any required channel attributes and can't create the channel until they're filled in. Channel attribute values can be viewed, edited, and added after creation from a new attributes section in **Channel Info**, subject to each attribute's change policy (any change, raise only, lower only, or never); locked attributes are shown read-only with the reason. The channel banner is now built from channel attribute values, and a manually configured banner still takes precedence. ``POST /api/v4/channels`` accepts channel attribute values and refuses to create a channel that is missing a required value.
 - Added a duplicate plugin upload confirmation modal that compares the installed plugin version with the uploaded plugin version before overwrite confirmation.
 - Replaced the plugin settings page enable setting with immediate plugin action buttons, and added an uninstall option from plugin settings.
 - Improved plugin upload UX in the System Console with an automatic upload dropzone, progress indicator, and clearer disabled-state messaging.
 - Added stricter server config validation for export, SQL replica monitor, feature flag sync, burn-on-read, LDAP group filter, Elasticsearch index sizing, connected workspace batch size, push notification buffer, log level, file storage, email, session, data retention, TLS, and webserver settings.
 - Added audit logging for new events caused by cached data deletion on mobile devices related to Mobile Ephemeral Mode settings.
 - Access rules can now compare a user's attributes with attributes of the channel being accessed, including ``hasAnyOf`` and ``hasAllOf`` for multi-value attributes, behind the new ``ResourceAttributesInPolicies`` feature flag. A rule that references a channel attribute denies access for every channel that has not set a value for it.
 - Extended personal access token lifetime enforcement, expiry notifications, and non-compliant token revocation to user-owned bot accounts. Plugin-owned and protected system bot accounts remain exempt.
 - Added webapp support for personal access token expiry and regeneration on user-owned bot accounts.
 - Applied channel file download permission policies to content reviewers.
 - Added a live Security Updates bulletin to the Security Guide that filters advisories by product, severity, issue ID, date, and affected version range.
 - Hid the System Console Recaps page unless the ``EnableAIRecaps`` feature flag is enabled.
 - Updated OAuth application management and authorization endpoint handling.
 - Updated team filter handling in the users listing API.
 - [Session attributes](https://docs.mattermost.com/administration-guide/manage/admin/session-attributes) (user agent, IP address, device/network posture) are now collected by default.
 - Updated file metadata preparation for post retrieval, channel bookmarks, and notification delivery.
 - Updated custom emoji image processing to use the shared image decoder, so animated GIF sources are subject to the configured maximum image resolution and image decoder concurrency.
 - Updated how EXIF metadata is read when determining image orientation.
 - Updated how database connection strings are reported in generated Support Packets and in server log output.

#### mmctl
 - Added ``--expires-in`` flag to ``mmctl bot create --with-token`` for personal access token lifetime enforcement on user-owned bot accounts.
 - Added ``--team-name`` and ``--team-id`` flags to ``mmctl export create`` to export a single team or a comma-separated list of teams instead of the full server.
 - Added ``--channel-name`` and ``--channel-id`` flags to ``mmctl export create`` to export a single channel or a comma-separated list of channels from a team.
 - Scoped exports from ``mmctl export create`` omit custom emoji by default to avoid pulling the source server's entire emoji library into the destination. Pass ``--include-custom-emoji`` to include them; reactions referencing custom emoji absent from the destination will render as literal ``:name:`` text otherwise.
 - Custom permission schemes assigned to exported teams are now preserved in the export.
 - Added ``--destination-team-name`` and ``--destination-team-id`` flags to ``mmctl import process`` to remap the exported team to a different team on the destination.
 - Added ``--destination-channel-name`` and ``--destination-channel-id`` flags to ``mmctl import process`` to remap the exported channel to a different channel on the destination.
 - Added ``--skip-preflight`` flag to ``mmctl import process`` to bypass the LDAP/SAML configuration check that runs before importing SSO users.
 - Import jobs now checkpoint progress and can be resumed after a crash or failure, including jobs interrupted by a hard process kill.
 - All users brought over by a scoped import land deactivated and tagged ``IMPORTED - INACTIVE`` pending admin review. Users who already exist on the destination are matched to their existing account and remain active.
 - When an imported user's username matches an existing destination account, their posts and reactions are attributed to that account instead of being dropped.
 - Posts referencing a channel that does not exist on the destination are skipped instead of aborting the entire import.
 - A role update that would demote the destination's only system admin is skipped instead of aborting the import.
 - A source user's historical deactivation date is preserved rather than overwritten with the import timestamp.

#### Performance

View the full raw data and methodology in our [Performance Reports repository](https://github.com/mattermost/performance-reports/tree/main/performance-comparisons/v12.0).
 - Improved performance of the bulk-indexing job for Elasticsearch and Opensearch for very large ``FileInfo`` and ``Channels`` tables.
 - Reduced database load by caching lookups of non-existent custom emoji names (e.g. emoji-like tokens in timestamps such as "11:11:11").
