## Release v12.2 - [Feature Release](https://docs.mattermost.com/product-overview/release-policy.html#release-types) \{#release-v12-2-feature-release}

**Release day: 2026-12-16**

### Upgrade Impact

#### Database Schema Changes
 - The following schema changes are included in this release. No database downtime is expected for this upgrade.
   - Added a ``permissions`` column (nullable JSONB) to the ``PropertyFields`` table.
   - Added a new ``PropertyFieldGrants`` table with columns ``FieldID``, ``Type``, ``ID``, and ``Action``, a composite primary key on those four columns, and a foreign key to ``PropertyFields`` with cascade delete.
   - Added a new index ``idx_propertyfieldgrants_type_id`` on ``PropertyFieldGrants (Type, ID, Action)``.
   - Added a new value ``'number'`` to the ``property_field_type`` enum.
   - Added a new value ``'checkbox'`` to the ``property_field_type`` enum.
   - Added a new value ``'everyone'`` to the ``permission_level`` enum.
   - Updated the ``PropertyGroups`` table to set ``Version`` to 3 for the ``access_control`` group.
   - Added a new index ``idx_channelmembers_channel_id_scheme_admin`` on ``ChannelMembers (ChannelId, UserId)`` where ``SchemeAdmin = true``.
   - Deleted the ``post_attributes`` property group and all associated rows from ``PropertyValues``, ``PropertyOptionEdges``, ``PropertyOptions``, ``PropertyFields``, and ``PropertyGroups``, and updated any ``post``-type fields in the ``access_control`` group with ``PermissionValues = 'member'`` to use ``'creator'`` instead.

#### config.json
New setting options were added to ``config.json``. Below is a list of the additions and their default values on install. The settings can be modified in ``config.json``, or the System Console when available.
 - **Changes to Enterprise Advanced Plans:**
   - Under ``CacheSettings`` in ``config.json``, added ``RedisEnableTLS`` configuration setting to enable TLS for Redis connections. See the [Redis: Secure Redis connections with TLS](https://docs.mattermost.com/deployment-guide/scale/redis#secure-redis-connections-with-tls) documentation for details.
   - Under ``CacheSettings`` in ``config.json``, added ``RedisTLSCA`` configuration setting to specify the TLS CA certificate for Redis connections.
   - Under ``CacheSettings`` in ``config.json``, added ``RedisTLSClientCert`` configuration setting to specify the TLS client certificate for Redis connections.
   - Under ``CacheSettings`` in ``config.json``, added ``RedisTLSClientKey`` configuration setting to specify the TLS client key for Redis connections.
   - Under ``CacheSettings`` in ``config.json``, added ``RedisTLSSkipVerify`` configuration setting to skip TLS verification for Redis connections.
 - **Changes to Enterprise Plans:**
   - Under ``ElasticsearchSettings`` in ``config.json``, added ``EnableFileIndexing`` configuration setting.
 - **Changes to All Plans:**
   - Under ``SSOSettings`` in ``config.json``, added ``AdditionalScopes`` configuration setting.
   - Under ``PluginSettings`` in ``config.json``, added ``RestrictUnauthenticatedWebappPlugins`` configuration setting to control whether unauthenticated requests to ``GET /api/v4/plugins/webapp`` only return plugins that set ``webapp.pre_auth``. Defaults to enabled for new installations; disabled on upgrade. See the [Web app plugins: Loading before login with preauth](https://docs.mattermost.com/developers/integrate/plugins/components/webapp#loading-before-login-with-pre_auth) documentation for details.
   - Under ``CloudSettings`` in ``config.json``, added ``PreviewLandingPath`` configuration setting for the path a cloud preview visitor lands on after the CWS login.

#### Important Upgrade Notes
 - Config validation now rejects a ``CacheSettings.RedisCachePrefix`` value that contains ``:``, ``*``, ``?``, ``[``, ``]``, or ``\`` when the Redis cache is enabled. A server already configured with such a prefix will fail config validation after upgrading and must change the prefix before restarting.
 - Allowed 0 (no limit) for ``TeamSettings.MaxUsersPerTeam`` and ``TeamSettings.MaxChannelsPerTeam``, and made 0 the default for new installations. Existing deployments keep their saved values. A server with either setting at 0 fails to start if downgraded to an earlier version that does not support 0.
 - ``LogSettings.EnableWebhookDebugging`` now defaults to false. When enabled, it logs failed incoming webhook requests with their payload, and System Console > Reporting > Site health shows a warning while it is on and debug logging is active. See the [Important upgrade notes](https://docs.mattermost.com/administration-guide/upgrade/important-upgrade-notes) documentation for details.
 - Sending email and testing the SMTP connection now return an error when SMTP Connection Security is set to STARTTLS and the SMTP server does not accept STARTTLS.
 - Starting with this release, FIPS builds reject SAML responses that use SHA-1, including RSA-OAEP key encryption with SHA-1 and SHA-1 signatures and digests, and the login fails. If your identity provider encrypts SAML assertions, configure it with RSA-OAEP-11 (``http://www.w3.org/2009/xmlenc11#rsa-oaep``), digest method SHA-256 (``http://www.w3.org/2001/04/xmlenc#sha256``), and MGF1-SHA256 (``http://www.w3.org/2009/xmlenc11#mgf1sha256``) set explicitly. See the [SAML Keycloak documentation](https://docs.mattermost.com/administration-guide/onboard/sso-saml-keycloak) for details. Non-FIPS builds are not affected.
 - Replaced the deprecated ``golang.org/x/crypto/openpgp`` library with ``github.com/ProtonMail/go-crypto`` for plugin signature verification and Team Edition to Enterprise upgrades. Plugin signatures and Team Edition to Enterprise upgrade signatures that use the SHA-1 hash algorithm, or that are made with a DSA key or an RSA key shorter than 2048 bits, are now rejected. Plugin signatures are also rejected if the signing key is expired, its self-signature lacks a signing key flag, or the signature uses the MD5 or RIPEMD-160 hash algorithms. Plugins signed with an admin-configured key using SHA-1 must be re-signed with SHA-256 or stronger; plugins signed with a DSA or short RSA key must be re-signed with a new key.
 - In High Availability deployments using Redis, cluster messages are now sent on a channel namespaced by ``CacheSettings.RedisCachePrefix``. Deployments that already set a prefix will not exchange cluster messages between old and new versions during a rolling upgrade.
 - Reserved the plugin ID ``com.mattermost.server``, including case variants, for the core server. Existing plugins with this ID will no longer load, and new installations and development reattachment are rejected.
 - Raised the minimum session attribute time-to-live and grace period to 1 minute. Existing session attributes configured with a TTL or grace period under 1 minute are migrated to 1 minute, and the 30-second option has been removed from the System Console.

<Important>

If you upgrade from a release earlier than v12.1, please read the other [Important Upgrade Notes](https://docs.mattermost.com/administration-guide/upgrade/important-upgrade-notes.html). In case of an upgrade failure, please check the [Downgrade Guide](https://docs.mattermost.com/administration-guide/upgrade/downgrading-mattermost-server.html) and the [Recovery Guide](https://docs.mattermost.com/deployment-guide/backup-disaster-recovery.html) for rollback steps and interim mitigation strategy.

</Important>

#### mmctl
 - ``mmctl system`` commands now propagate context, so Ctrl+C and SIGTERM cancel in-flight API calls cleanly.
 - Added [``mmctl logs``](https://docs.mattermost.com/administration-guide/manage/mmctl-command-line-tool) flags ``--follow``, ``--interval``, ``--level``, ``--node``, ``--search`` (``-s``) and ``--since``. ``mmctl logs`` now reads logs through ``POST /api/v4/logs/query``, which requires JSON file logging (``LogSettings.FileJson``) for filtering and following; with plain-text log files it prints the logs unfiltered as before. ``--follow``, ``--level``, ``--node``, ``--search`` and ``--since`` require a v12.2 or later server. ``mmctl logs`` now always uses the logrus format, colored on a terminal (set ``NO_COLOR`` to turn colors off), and shows when the server logged each entry. The ``--logrus`` flag is deprecated.
 - Added the ``--plugin`` flag to [``mmctl logs``](https://docs.mattermost.com/administration-guide/manage/mmctl-command-line-tool), which shows only the log entries of the given plugin IDs. Added shell completion of plugin IDs to ``mmctl logs --plugin`` and ``mmctl plugin enable``, ``disable`` and ``delete``.
 - Added ``mmctl plugin keys``, ``mmctl plugin keys add``, and ``mmctl plugin keys delete`` commands (local mode only) to manage plugin signature public keys, along with local-mode API endpoints under ``/api/v4/plugins/public_keys``.

#### Performance
 - Improved the performance of loading and filtering server logs in the System Console, and streamed log downloads instead of loading the whole log file into memory.
 - Improved Server Logs performance in the System Console when filtering by a date range in the past.
 - Improved link metadata caching for posts that include permalink previews.
 - Server Logs searches now stop after 20 seconds or 1 GiB of log file per node. The ``POST /api/v4/logs/query`` and ``GET /api/v4/logs`` responses then end with an entry that has ``scan_limited`` set to true and ``scanned_back_to`` set to the oldest timestamp read, and the System Console shows how far back each node searched. A new search in the System Console now cancels the previous one instead of waiting for it.
 - Updated the default page size used when reading a thread or a channel's pinned posts.

**Breaking Changes**
 - Starting with v12.0.2, new installations support post messages of up to 262,144 characters, with the ``message`` column on ``posts``, ``drafts``, ``scheduledposts`` and ``temporaryposts`` created as ``VARCHAR(1048576)``. Existing installations keep their current column sizes and maximum message length. The maximum message length is a quarter of the ``Posts.Message`` column size, to allow for characters of up to four bytes.
 - Several pre-packaged plugins received major version updates in v12.0 because they required changes to run on this release without errors. Web app plugins that have not been rebuilt for v12.0 may have their activation suppressed to prevent runtime errors. Before upgrading, update community-built plugins to a release that supports v12.0, and rebuild and test any self-built plugins against v12.0. See the React 19 note in this section for the APIs removed in that version and the codemod for updating a plugin.
 - Dropped support for RHEL 7 and RHEL 8. The server binary now requires glibc 2.34 or later (reported on Linux).
 - Dropped support for OpenSearch 1.x. Mattermost now requires OpenSearch 2.x or newer, and logs an error on startup when connected to an unsupported version.
 - ``atmos/camo`` is no longer supported as an image proxy. If ``ImageProxySettings.ImageProxyType`` is set to ``atmos/camo``, the server automatically changes it to ``local`` on startup and logs a warning. If image proxying is enabled, images are then proxied by the Mattermost server itself instead of the external ``atmos/camo`` service, so the server must be able to reach the external hosts that images are loaded from. The ``RemoteImageProxyURL`` and ``RemoteImageProxyOptions`` settings have also been removed and are ignored.
 - The minimum supported PostgreSQL version is now v15. PostgreSQL v14 and earlier are no longer supported.
 - The ``MoveThreadsEnabled`` feature flag is no longer supported. If it is enabled, the server turns it off on startup and logs a warning. Use https://github.com/mattermost/mattermost-plugin-wrangler instead.
 - The ``AppsEnabled`` feature flag is no longer supported. If it is set to ``true``, the server turns it off on startup and logs a warning.
 - Removed the deprecated built-in Slack import API and CLI. The ``POST /teams/{team_id}/import`` endpoint and the ``mattermost import slack`` command are no longer available. Use the [mmetl tool with ``mmctl import``](https://docs.mattermost.com/administration-guide/onboard/migrate-from-slack.html) instead.
 - Removed deprecated Slack compatibility type aliases and functions (``SlackAttachment``, ``SlackAttachmentField``, ``ParseSlackAttachment``, ``StringifySlackFieldValue``) from the Go package. Use ``MessageAttachment``, ``MessageAttachmentField``, ``ParseMessageAttachment``, and ``StringifyMessageAttachmentFieldValue`` instead.
 - The ``POST /api/v4/logs/query`` API now returns HTTP 400 when ``date_from`` or ``date_to`` is a non-empty value that cannot be parsed with the layout ``"2006-01-02 15:04:05.999 -07:00"``. Previously such values were silently ignored and the request returned HTTP 200 with unfiltered results. Empty values continue to mean "unbounded".
 - Removed the required ``format`` query parameter from the ``GET /api/v4/license/client`` endpoint. The endpoint now returns the client license information without requiring format specification.
 - Removed the ``EnableConcurrentReact`` feature flag. The web app now always renders with concurrent React.
 - Post identity and display-override props (``from_webhook``, ``from_bot``, ``from_oauth_app``, ``from_plugin``, ``override_username``, ``override_icon_url``, ``override_icon_emoji``, ``webhook_display_name``) are no longer accepted from regular user or personal access token sessions. They are stripped on create/update and only re-applied for verified integrations (incoming webhooks and slash commands for overrides; bots/OAuth/plugins for ``from_*`` markers). Scripts that forged ``from_webhook`` and ``override_*`` via a user personal access token to post under a custom name/icon must migrate to a bot account or an incoming webhook. ``EnableHardenedMode`` no longer rejects reserved post props with HTTP 400; it continues to control login/MFA/password-reset/5xx scrubbing only.
 - Removed deprecated interactive dialog date/datetime fields. Top-level ``min_date``, ``max_date``, and ``time_interval``, and ``datetime_config.allow_manual_time_entry``, are no longer accepted; use ``datetime_config`` (with ``manual_time_entry``) instead. Legacy keys are silently ignored.
 - Auto-adding members to a channel or team with an attribute-based access policy is now stored on the policy's membership rule instead of the policy's active flag, and is set per channel and per team. Existing settings are migrated automatically. Clients using ``PUT /api/v4/access_control_policies`` to set the ``active`` field to control auto-adding must set the membership rule's ``auto_add`` metadata instead; the ``/access_control_policies/activate`` endpoint continues to work unchanged (reported on webapp).
 - A custom attribute field with more than 1000 options now serializes a count in place of its option list.
 - Removed the ``EmailLoginButtonColor``, ``EmailLoginButtonBorderColor``, and ``EmailLoginButtonTextColor`` client configuration fields alongside the ``EmailSettings`` login button color settings. These fields were never applied by any client.
 - The channel member API endpoints no longer return ``last_viewed_at`` and ``last_update_at`` for other users' memberships. ### Upgrade Impact

#### Database Schema Changes
 - The following schema changes are included in the v12.0 release. No database downtime is expected for this upgrade.
   - Dropped the partial index ``idx_channelmembers_autotranslation_enabled`` from ``channelmembers`` non-blocking using ``CONCURRENTLY``; no downtime or query correctness impact expected.
   - Migration 000215 removed the long-deprecated ``autotranslation`` column from ``channelmembers`` via a fast catalog-only operation with no table rewrite and minimal locking impact.
   - Split the ``AttributeView`` materialized view into ``UserAttributeView`` and ``ChannelAttributeView`` for independent ABAC attribute querying; no performance impact expected as tables are feature-flagged and empty in production.
   - Starting with v12.0.2, the ``message`` columns on ``posts``, ``drafts``, ``scheduledposts``, and ``temporaryposts`` are created as ``VARCHAR(1048576)`` on new installations only, raising the maximum message length from 16,383 to 262,144 characters.
   - Added new ``PostDeliveryTrackingChannels`` table with a unique index on ``ChannelId`` to support post-delivery tracking; no impact on existing tables or queries.
   - Added composite index ``idx_fileinfo_create_at_id`` on ``Fileinfo(CreateAt, Id)`` using ``CONCURRENTLY`` to improve file query performance with no downtime impact.
   - Added composite index ``idx_channels_create_at_id`` on ``Channels (CreateAt, Id)`` to accelerate cursor-based pagination; no downtime expected, minimal impact on concurrent operations.
   - Added ``DisableJoinLeaveMessages`` boolean column to ``Channels`` table to support per-channel suppression of join/leave messages; metadata-only change with no table rewrite and negligible downtime impact.
   - Added ``graph`` value to the ``property_field_type`` enum to support a new property field variant; no user tables are affected and impact on running systems is negligible.
   - Migration 000223 extracted property field options from a JSON blob in ``PropertyFields`` into new ``PropertyOptions`` and ``PropertyOptionEdges`` tables and rebuilt ``UserAttributeView`` and ``ChannelAttributeView``; deployments with large ``PropertyValues`` tables may experience brief query stalls on those views during migration.
   - Added partial composite index ``idx_propertyoptions_fieldid_createat_id`` on ``PropertyOptions(FieldID, CreateAt, ID) WHERE DeleteAt = 0`` to accelerate keyset pagination of live property options with no read/write impact.
   - Added partial composite index ``idx_propertyoptions_fieldid_name`` on ``PropertyOptions(FieldID, Name) WHERE DeleteAt = 0`` to speed up name-resolution lookups within the properties system; no downtime required.
   - Added a non-blocking composite index on ``PropertyOptionEdges (FieldID, ParentOptionID, ChildOptionID)`` to accelerate field-scoped property option hierarchy traversal with no read/write impact.
   - Backfilled ``auto_add: "always"`` metadata into ``AccessControlPolicies`` membership rules, migrating automatic-member behavior from the ``Active`` column to per-rule metadata with no performance impact.
   - Added GIN index ``idx_access_control_policies_rules`` on ``AccessControlPolicies(Data -> 'rules')`` to speed up access-control policy membership lookups with no downtime or locking impact.
