Work through the [troubleshooting steps](#troubleshooting-steps) for any desktop app problem, or jump to a known issue below. [Advanced operations](#advanced-operations) covers where the app stores data, seeding `config.json`, and hosting spell checker dictionaries.

## Troubleshooting steps

1.  **Try it in a browser.** Sign in to the same server in a web browser, including a private window. If the problem happens there too, it's a server or web app issue. See [Deployment troubleshooting](/deployment-guide/server/troubleshooting). If the server doesn't load at all in the desktop app, check for errors in **View \> Developer Tools \> Developer Tools for Current Tab**.
2.  **Reload.** Press <kbd>Ctrl</kbd> <kbd>R</kbd> (<kbd>⌘</kbd> <kbd>R</kbd> on macOS). If that doesn't help, clear the cache with **View \> Clear Cache and Reload**, or <kbd>Ctrl</kbd> <kbd>Shift</kbd> <kbd>R</kbd> (<kbd>⌘</kbd> <kbd>⇧</kbd> <kbd>R</kbd> on macOS).
3.  **Restart.** Quit and reopen the app, then restart the computer if needed.
4.  **Reset.** Select **View \> Clear Data for Current Server**. If that doesn't help, select **View \> Clear All Data**, which erases session, cache, cookie, and storage data for all servers and signs the user out. If the app won't start, delete the [app data folder](/deployment-guide/desktop/desktop-troubleshooting#where-the-app-stores-data), which also removes the user's servers and settings. On Windows and Linux, the folder contains the app's logs, so copy them first if you need them for [debugging](#collect-debugging-information).
5.  **Check known issues.** Search the [changelog](/product-overview/desktop-app-changelog) and [GitHub issues](https://github.com/mattermost/desktop/issues?q=is%3Aissue), and try the latest release.
6.  **Collect information and contact support.** See [Collect debugging information](#collect-debugging-information).

### Collect debugging information

- **Debug logs**: In **Settings \> Advanced**, set **Logging level** to **Debug**, reproduce the problem, then select **Help \> Show logs** to find the log file. We recommend setting the logging level back afterwards, because debug logging slows the app down.
- **Diagnostics**: Select **Help \> Run diagnostics**.
- **Console logs**: Select **View \> Developer Tools \> Developer Tools for Current Tab**, open the **Console** tab, then right-click a log entry and select **Save As**.
- **Memory usage**: If the app uses a lot of memory or is slow, take a [heap snapshot](https://developer.chrome.com/docs/devtools/memory-problems/heap-snapshots) from **Developer Tools for Current Tab**. A heap snapshot can contain message content from the signed-in workspace, so share it only through an approved process.

Review these files with your administrator and remove any sensitive data before attaching them to a [support ticket](https://support.mattermost.com/hc/en-us/articles/360060662492-Opening-a-Support-Ticket-for-Self-Managed-Deployments).

## Installation and updates

### Update notifications don't appear

- Your admin may have disabled the `EnableAutoUpdater` [policy](/deployment-guide/desktop/desktop-app-policies).
- The app checks for updates at `releases.mattermost.com`, so it needs network access to that host.
- If **Skip This Version** was selected, the app doesn't notify you about that version again. You can still check manually with **Help \> Check for Updates**.

### The update required screen appears

The server requires a newer desktop app version. **Download** opens the page where you can get the update, or you can contact your admin. Admins, see [Enforce a minimum version](/deployment-guide/desktop/desktop-app-deployment#enforce-a-minimum-version).

## Startup and display

### The app window is black

Try clearing **Settings \> Advanced \> Use GPU hardware acceleration**, then restarting the app. If you use a graphics switching driver, such as NVIDIA Optimus, disabling it may also help.

### The app is running but its window isn't visible

This can happen after disconnecting the monitor the app was on. To reset the window position, quit the app, delete `bounds-info.json` from the [app data folder](#where-the-app-stores-data), then reopen the app. It opens on the primary monitor.

### The window can't be made smaller

The app may be in full screen. **View \> Toggle Full Screen** switches it back.

### The app constantly refreshes

Deleting the `Local Storage` folder from the [app data folder](/deployment-guide/desktop/desktop-troubleshooting#where-the-app-stores-data) while the app is closed usually fixes this.

### The app has problems on a virtual desktop

See the [VDI frequently asked questions](/deployment-guide/desktop/desktop-vdi-deployment#frequently-asked-questions), which cover Citrix responsiveness and `EEXIST` errors on Omnissa Horizon.

## Sign-in and servers

### Sign-in doesn't return to the app

Sign-in with SSO opens the browser, then returns to the app through a `mattermost://` link. If that doesn't work:

- On Windows or macOS, try reinstalling the app, or using a different default browser.
- On Linux with the tarball, run `create_desktop_file.sh` to register the app with your desktop environment. See [Deploy the desktop app on Linux](/deployment-guide/desktop/linux-desktop-install).

### Users are signed out after updating the app

Some updates change how the app stores session data. Users need to sign in again once.

### The server URL changes when adding a server

The app replaces the URL with the server's [Site URL](/administration-guide/configure/environment-configuration-settings#site-url). If the Site URL is wrong, ask your admin to correct it.

### A certificate error appears

The server, or content embedded in a message such as an image, uses a certificate the app doesn't trust. Ask your admin to fix the server's certificate. For embedded images, admins can enable the [image proxy](/administration-guide/configure/environment-configuration-settings#enable-image-proxy).

### Servers set by policy don't appear

The app reads policies when it starts, so it needs to be restarted after the policy is applied. On Windows, you can check that the servers are listed in `HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Mattermost\DefaultServerList`. See [Policies](/deployment-guide/desktop/desktop-app-policies).

### Deep links open in the wrong server

Links open in the server whose URL matches them exactly, including protocol and subdomain, so it's worth checking the server URLs in the app and correcting or removing stale servers. Pre-provisioning servers with the `DefaultServerList` [policy](/deployment-guide/desktop/desktop-app-policies) keeps URLs consistent.

## Notifications, calls, and permissions

The desktop app needs permission from the operating system, and the app must grant permission to each server. To check a server's permissions, select the server in the top left of the app, edit it, and review **Permissions**.

### Notifications don't appear

**Notifications** needs to be turned on both in the server's permissions and in your operating system's settings. See [Troubleshoot notifications](/end-user-guide/preferences/troubleshoot-notifications).

### Notifications appear more than once

This can happen with several tabs or pop-out windows open for the same server. Closing the extras usually stops it.

### The microphone or camera doesn't work in calls

**Microphone and Camera** needs to be turned on both in the server's permissions and in your operating system's settings.

## Performance

### Memory or CPU usage is high

Reloading the app, and closing tabs, pop-out windows, and servers you don't use, usually reduces it. If it continues, a [heap snapshot](#collect-debugging-information) helps support find the cause.

### The app freezes

Endpoint security software can interfere with the app. Excluding Mattermost from endpoint security scanning may help, so check with your admin.

### "BrowserWindow 'unresponsive' event" error

Try **View \> Clear Cache and Reload**. If it continues, try clearing **Settings \> Advanced \> Use GPU hardware acceleration**, then restarting the app.

## Spell check doesn't work

On Windows and Linux, the app downloads dictionaries, which your network may block. Debug logs show spell checker errors if this is the cause. See [Spell checker dictionaries](/deployment-guide/desktop/desktop-troubleshooting#spell-checker-dictionaries).

## Advanced operations

### Where the app stores data

Each user's `config.json`, sign-ins, caches, and logs are stored in their app data folder:

| Platform | App data folder | Logs |
|---|---|---|
| Windows | `%APPDATA%\Mattermost` | `%APPDATA%\Mattermost` |
| macOS (DMG) | `~/Library/Application Support/Mattermost` | `~/Library/Logs/Mattermost` |
| macOS (Mac App Store) | `~/Library/Containers/Mattermost.Desktop/Data/Library/Application Support/Mattermost` | `~/Library/Containers/Mattermost.Desktop/Data/Library/Logs/Mattermost` |
| Linux (Flatpak) | `~/.var/app/com.Mattermost.Desktop/config/Mattermost` | `~/.var/app/com.Mattermost.Desktop/config/Mattermost` |
| Linux (other packages) | `~/.config/Mattermost` | `~/.config/Mattermost` |

Uninstalling the app doesn't remove this folder.

### Seed config.json

As an advanced option, you can use `config.json` to set initial servers and settings, such as hardware acceleration, autostart, error reporting, or session attributes. The file goes in the user's [app data folder](#where-the-app-stores-data) before they first launch the app. Overwriting an existing file replaces the user's own servers and settings, so it's best to only create it when it's missing.

**Example config.json:**

``` json
{
  "version": 4,
  "servers": [
    {
      "name": "core",
      "url": "https://community.mattermost.com",
      "order": 0
    },
    {
      "name": "hq",
      "url": "https://hq.example.com",
      "order": 1
    }
  ],
  "showTrayIcon": true,
  "trayIconTheme": "light",
  "minimizeToTray": true,
  "notifications": {
    "flashWindow": 2,
    "bounceIcon": true,
    "bounceIconType": "informational"
  },
  "showUnreadBadge": true,
  "useSpellChecker": true,
  "enableHardwareAcceleration": true,
  "autostart": false,
  "spellCheckerLocales": ["en-US"],
  "darkMode": false
}
```

#### Seed config.json on Windows

The app data folder is per-user, so the copy step must run as the signed-in user, not as `SYSTEM`. Common ways to do this:

- **Separate user-context deployment**: A second script that only copies `config.json`, configured to run as the user (Intune: **Install behavior** set to **User**; SCCM: **Installation behavior** set to **Install for user**), with a dependency on the system-context MSI deployment.
- **Active Setup**: The system-context install registers an Active Setup `StubPath` command (under `HKLM\SOFTWARE\Microsoft\Active Setup\Installed Components`) that copies `config.json`. Windows runs it once for each user at their next sign-in.
- **Logon script**: A Group Policy logon script copies the file.

``` batch
@echo off
rem Run as the signed-in user, not as SYSTEM.
if exist "%APPDATA%\Mattermost\config.json" exit /b 0
if not exist "%APPDATA%\Mattermost" mkdir "%APPDATA%\Mattermost"
copy "\\SERVER\shared_folder\config.json" "%APPDATA%\Mattermost\config.json"
```

### Spell checker dictionaries

On Windows and Linux, the app downloads Hunspell dictionaries from Chromium's CDN. On macOS, it uses the dictionaries provided by Apple. If your network blocks the CDN, you can host the dictionaries yourself:

1.  Download `hunspell_dictionaries.zip` from the [latest Electron release](https://github.com/electron/electron/releases/latest), and extract it.
2.  Rename the files to lowercase. For example, `en-US` becomes `en-us`.
3.  Serve the files from a web server.
4.  Point the app at the folder URL, either with `"spellCheckerURL": "https://<your-server>/<folder>/"` in [config.json](#seed-configjson), or in **Settings \> Language \> Use an alternative dictionary URL**.
